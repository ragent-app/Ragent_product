# Linux 与 macOS 发行计划

## 目标与范围

以 Windows 已交付的安装、启动、会话、权限审批、设备连接和更新体验为对照，
逐项确认 Linux 和 macOS 的支持范围。发布声明必须限定到经过验收的系统版本、
架构和功能；能构建或能启动不等于达到发行标准。

首批候选以 Linux Debian 系安装包和 macOS Apple Silicon 应用为主。其他发行版、
Linux ARM64、Intel Mac、最低系统版本和发行渠道，均须有对应环境及验收证据，
不能仅凭交叉编译或模拟测试宣布支持。安装包的源代码提交、版本、构建依赖、
摘要及测试环境须记录在每个候选的验收记录中。

## 当前进展和边界

- Linux Debian 候选已在隔离的 Ubuntu 24 WSL 实例中验证安装、升级、服务、
  桌面管理器和模拟提供商任务。0.0.16 候选由提交 `6ff7864` 的 Git 对象
  构建，并通过从 0.0.14 升级及配置保留检查。WSL 与虚拟显示不能替代物理 Linux 桌面验收；
  模拟任务也不能替代真实提供商账户调用或 Android 端到端连接。
- macOS Apple Silicon 已在真机完成隔离测试包构建、ad-hoc 签名、镜像挂载、
  应用复制、内置运行时版本、服务健康、重复启动、停止、配置保留和桌面
  管理器进程启动检查。0.0.17 测试包由提交 `d2375a9` 的 Git 对象构建，
  并记录了预编译 P2P 输入的摘要；窗口显示和交互尚未人工验收。
- macOS 的语义审批编译器、目标解析器和权限目标校验器尚不支持 `darwin`，
  也没有经过验收的同等主机权限执行链。不得宣称权限审批与 Windows 等价。
- macOS 的 Developer ID 签名、公证、装订和 Gatekeeper 验收尚未完成。
  ad-hoc 签名仅用于受控测试，不能作为直接分发的信任证明。

## 必须完成的工作

1. **明确发行矩阵。** 冻结支持的系统版本、架构、安装方式和各平台功能；
   针对不支持的功能，在产品界面和发行说明中明确提示。
2. **Linux 安装与生命周期。** 在干净的目标发行版上验收普通用户安装、
   首次配置、服务自启动、异常恢复、升级、卸载、数据保留和回滚。确认
   已存在的用户命令和数据不被覆盖；物理桌面验证管理器及其图形依赖。
3. **macOS 安装与生命周期。** 在干净的受支持 Mac 上验证从 DMG 复制到
   Applications、Finder 启动、首次配置、再次启动、登录自启动、端口冲突、
   服务异常恢复、升级、卸载和回滚。升级必须保留用户配置、凭据和工作区。
4. **macOS 权限审批。** 为受支持的操作设计 macOS 专用的命令语义和目标
   解析，处理路径规范化、符号链接、大小写、挂载点、受保护目录及系统服务
   等平台差异；未知语法和无法证明的目标保持拒绝。将审批结果绑定到完整
   操作、用户会话、目标身份和一次性授权，执行前重新解析与复核，保留审计。
   为需要更高权限的操作设计独立、最小权限的本机执行组件，并验证其安装、
   身份、授权、升级及卸载；不能把 Linux 的命令或安全假设直接当成 macOS
   实现，也不能使用未验证的脚本提权作为安全边界。
5. **沙箱与权限对齐。** 核对每种风险模式下的实际进程身份、目录访问、
   网络访问、子进程清理和越权边界；区分提供商自身沙箱与产品执行层保护。
   跨用户、符号链接替换、授权重放、超时、拒绝和故障均需负向测试。
6. **真实功能验收。** 在隔离测试账户下，逐个验证已声明支持的提供商登录、
   真实任务、流式结果、取消、断网和恢复；验证项目、会话、文件操作、历史、
   审批与重启恢复。不得使用或打包真实用户现有凭据。
7. **设备与网络。** 使用授权测试账户及真实 Android 设备验证账户绑定、
   配对、直接连接和中继、会话交互、网络切换与断线恢复；记录服务依赖和
   失败行为。离线协议或加密测试只能作为补充证据。
8. **供应链与发行。** 从单一干净提交和锁定依赖构建，核验组件架构、摘要、
   签名及第三方许可；发布负责人确认 Claude Code 等预装条款。macOS 必须
   使用 Developer ID Application 证书完成签名、公证、装订和干净机器上的
   Gatekeeper 验证。检查更新元数据与实际产物摘要一致，保留已验证的回滚包。
9. **文档和支持。** 完成系统要求、安装、首次登录、权限、数据位置、升级、
   卸载、故障诊断、隐私和已知限制说明，建立可重复执行的发布检查表。

## 阶段验收与发布门槛

先完成各平台安装和运行闭环，再完成权限与真实任务、设备和网络，最后对
冻结提交执行全量发行验收。每一阶段记录测试范围、实际环境、结果、失败和
剩余问题；发现会导致数据丢失、越权、无法安装或无法启动的问题时停止发布。

各平台独立放行。只有对应矩阵全部关键项通过、签名和许可条件满足、回滚
方案可用后，才可将该平台标记为可发行。详细的逐项检查见
[桌面发行验收清单](desktop-release-validation.md)。
