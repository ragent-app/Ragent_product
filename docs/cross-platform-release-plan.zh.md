# Linux 与 macOS 发行计划

## 目标与范围

以 Windows 已交付的安装、启动、会话、权限审批、设备连接和更新体验为对照，
逐项确认 Linux 和 macOS 的支持范围。发布声明必须限定到经过验收的系统版本、
架构和功能；能构建或能启动不等于达到发行标准。

首批候选以 Linux Debian 系安装包和 macOS Apple Silicon 应用为主。其他发行版、
Linux ARM64、Intel Mac、最低系统版本和发行渠道，均须有对应环境及验收证据，
不能仅凭交叉编译或模拟测试宣布支持。安装包的源代码提交、版本、构建依赖、
摘要及测试环境须记录在每个候选的验收记录中。

  构建，并通过从 0.0.14 升级及配置保留检查。0.0.19 测试包从提交

  为 `dd5fec402a7f24ae926ca08ee89c21a7fbec88d8f3f071411ffd7f3b8f77b4d9`；
  在同一隔离实例中，从 0.0.16 升级、普通卸载和重新安装均通过，检查了
  选定的配置文件摘要、服务停启及健康接口。另以运行在产品任务 slice 中的
  模拟进程验证普通卸载会停止该进程并保留所检查的配置；随后通过产品接口
  启动持续运行的离线模拟提供商任务，验证其进程属于产品任务 slice、卸载时
  被停止且所检查配置保留。真实外部提供商任务执行期间的卸载仍需验证。

  并确认批准和拒绝响应均送达提供商进程；全自动模式也拒绝了夹具中的危险请求。
  夹具不执行所请求命令，真实账户、实际命令和移动端审批往返仍需验证。

  保存回复；这不代表外部模型账户或联网调用通过验收。
  0.0.20 测试包由提交 `9978ed8b082f94c7919c349630307b6fe2f997b0` 构建，
  SHA-256 为 `d1dd811713cfc683b37d075e699f541e1ade9f0ea0d52e2cf38b5c4e3b8ca469`；
  在同一 WSL 实例从 0.0.19 升级后，所检查配置和健康接口正常，内置 Codex

  已有 systemd 任务单元按匹配身份和进程重用，并取消测试任务。
  当时未验证完整数据集、清除卸载或物理桌面。

  主目录账户迁移，并完成真实 Codex 任务。0.0.26 候选由提交
  `714c63cbcd4783a05002e9398eec2aa3aabf8306` 构建，SHA-256 为
  `00ea6b667fc8e58789239ef1c5216facb39e7deaef0155a07546920001051a4a`。

  Run 进入 `cancelled`，对应 systemd 单元退出并回收，未观察到该测试命令

  不覆盖服务重启、物理桌面或真实用户数据集。
  WSL 与虚拟显示不能替代物理 Linux 桌面验收；
  模拟任务也不能替代真实提供商账户调用或 Android 端到端连接。

  这不等于真实账户联网、完整界面操作或权限审批已通过验收。自启动管理
  工具已在真机使用 `eff2bbe` 构建的 0.0.18 测试包验证实际服务注册、
  健康检查、进程异常退出后恢复、停用和配置保留；真实退出并重新登录及
  正式安装包的升级仍需验收。
- 2026-11-12 在同一 Apple Silicon Mac 上，以提交 `d350656` 的冻结 Git
  对象构建 0.0.26 ad-hoc 测试镜像（SHA-256：
  `c76dd4dc4d71c5a6f432ab10e25696a5b5d18437fcaf1d4d8182bd7af524d41c`）。
  预编译 P2P 输入的 SHA-256 为

  该提交相对 0.0.18 所用提交的 P2P 源码无变化。隔离测试验证了复制后的

  注册、进程异常后恢复和停用。另将隔离目录中的 0.0.18 应用替换为 0.0.26，
  确认前后服务健康且测试配置、生成凭据和工作区文件摘要不变。该测试没有

  命令进程仍存活超过 45 秒；另一次验证在取消后 5 秒仍观察到进程。测试

  但标识本身不能证明进程身份或安全地解决并发和 PID 复用问题。修复并在
  真机复验之前，不得宣称 macOS 的取消和进程清理验收通过。
- 后续提交 `b53ba9f` 为 macOS 共享 Codex 服务加入同用户的任务进程清理：
  从已绑定的线程取得 Run 标识，只检查服务进程的后代，核对进程 UID 和
  启动时间后发送信号。原生组件测试覆盖另一任务、仅命令行伪造标识以及

  `e8ba12901878cefd56def90e2193dd82ebf3195c62a3022a7d2b5fd9d194042c`。
  在同一 Mac 上使用真实 Codex OAuth 同时运行两个隔离任务，取消其中一个
  后其 Python 进程约 1.2 秒内退出，另一个任务仍运行；测试完成后服务健康。
  这消除了上述复现案例，并非完整的进程隔离保证：清理前已丢失标识或脱离
  服务进程树的进程、扫描期间创建的新进程、系统拒绝读取进程信息、PID
  身份检查与信号之间的竞态，以及正式签名环境仍须单独处理或验收。
- 提交 `b6d837c` 和 `18dd00e` 增加清理结果反馈：未确认时保留取消请求，
  在会话历史中显示警告，并通过受作用域保护的任务接口返回 `unconfirmed`；
  `attempted` 只表示已尝试清理，不表示所有进程均已停止。Mac 实机故障
  注入验证了组件缺失时的警告、持久化历史和接口结果；使用的是 0.0.28
  隔离包叠加已提交代码的修改副本，不能替代最终干净构建验收。上游伪造
  清理通知的负向检查已通过。组件正常时的新结果字段仍需真机完整复验。
- macOS 仅有少量命令的非授权语义识别预览，目标解析器和权限目标校验器
  尚不支持 `darwin`，也没有经过验收的同等主机权限执行链；识别结果仍全部拒绝。不得宣称权限审批与 Windows 等价。
- macOS 的 Developer ID 签名、公证、装订和 Gatekeeper 验收尚未完成。
  ad-hoc 签名仅用于受控测试，不能作为直接分发的信任证明。

## 必须完成的工作

1. **明确发行矩阵。** 冻结支持的系统版本、架构、安装方式和各平台功能；
   针对不支持的功能，在产品界面和发行说明中明确提示。
2. **Linux 安装与生命周期。** 在干净的目标发行版上验收普通用户安装、
   首次配置、服务自启动、异常恢复、升级、卸载、数据保留和回滚。确认
   已存在的用户命令和数据不被覆盖；物理桌面验证管理器及其图形依赖。
3. **macOS 安装与生命周期。** 在干净的受支持 Mac 上验证从 DMG 复制到
   Applications、Finder 启动、首次配置、再次启动、登录自启动、端口冲突、
   服务异常恢复、升级、卸载和回滚。升级必须保留用户配置、凭据和工作区。
4. **macOS 权限审批。** 为受支持的操作设计 macOS 专用的命令语义和目标
   解析，处理路径规范化、符号链接、大小写、挂载点、受保护目录及系统服务
   等平台差异；未知语法和无法证明的目标保持拒绝。将审批结果绑定到完整
   操作、用户会话、目标身份和一次性授权，执行前重新解析与复核，保留审计。
   为需要更高权限的操作设计独立、最小权限的本机执行组件，并验证其安装、
   身份、授权、升级及卸载；不能把 Linux 的命令或安全假设直接当成 macOS
   实现，也不能使用未验证的脚本提权作为安全边界。具体的信任边界、目标
   复核和验收要求见 [macOS 审批与执行组件设计](macos-approval-execution-design.zh.md)。
5. **沙箱与权限对齐。** 核对每种风险模式下的实际进程身份、目录访问、
   网络访问、子进程清理和越权边界；区分提供商自身沙箱与产品执行层保护。
   跨用户、符号链接替换、授权重放、超时、拒绝和故障均需负向测试。
6. **真实功能验收。** 在隔离测试账户下，逐个验证已声明支持的提供商登录、
   真实任务、流式结果、取消、断网和恢复；验证项目、会话、文件操作、历史、
   审批与重启恢复。不得使用或打包真实用户现有凭据。
7. **设备与网络。** 使用授权测试账户及真实 Android 设备验证账户绑定、
   配对、直接连接和中继、会话交互、网络切换与断线恢复；记录服务依赖和
   失败行为。离线协议或加密测试只能作为补充证据。
8. **供应链与发行。** 从单一干净提交和锁定依赖构建，核验组件架构、摘要、
   签名及第三方许可；发布负责人确认 Claude Code 等预装条款。macOS 必须
   使用 Developer ID Application 证书完成签名、公证、装订和干净机器上的
   Gatekeeper 验证。检查更新元数据与实际产物摘要一致，保留已验证的回滚包。
9. **文档和支持。** 完成系统要求、安装、首次登录、权限、数据位置、升级、
   卸载、故障诊断、隐私和已知限制说明，建立可重复执行的发布检查表。

## 阶段验收与发布门槛

先完成各平台安装和运行闭环，再完成权限与真实任务、设备和网络，最后对
冻结提交执行全量发行验收。每一阶段记录测试范围、实际环境、结果、失败和
剩余问题；发现会导致数据丢失、越权、无法安装或无法启动的问题时停止发布。

各平台独立放行。只有对应矩阵全部关键项通过、签名和许可条件满足、回滚
方案可用后，才可将该平台标记为可发行。详细的逐项检查见
[桌面发行验收清单](desktop-release-validation.md)。


## 交付顺序、依赖与工作量

以下为规划估算，单位为熟悉现有项目的工程师人日；可并行工作不应简单相加
作为日历工期。估算不含 Apple 审核、账户开通、外部服务等待和未知兼容性问题，
完成平台清单和权限方案评审后应重新估算。

| 阶段 | 主要交付 | 估算 | 前置条件和验收 |
| --- | --- | --- | --- |
| 发行基线 | 功能对照矩阵、支持范围、环境和测试账户清单 | 2–4 人日 | Windows 行为及各平台差异可逐项追踪 |
| Linux 生命周期 | 安装、服务、升级、卸载、数据迁移与桌面问题修复 | 5–10 人日 | 目标物理机安装和升级测试通过 |
| macOS 生命周期 | DMG、Finder、登录启动、升级卸载及异常恢复 | 6–12 人日 | 干净 Mac 人工验收通过 |
| macOS 权限与隔离 | 威胁模型、平台语义、最小权限执行组件与负向测试 | 15–30 人日 | 安全设计评审、授权绑定及越权测试通过；范围变化可显著影响工期 |
| 功能和设备联调 | 真实提供商、桌面流程、Android 配对和网络恢复 | 8–15 人日 | 隔离测试账户、真实设备及必要服务可用 |
| 发行流水线与文档 | 冻结构建、许可、签名、公证、更新、回滚和支持文档 | 6–12 人日 | 证书、发布渠道和构建环境就绪 |
| 最终回归 | 对同一冻结提交和最终包进行平台矩阵验收 | 4–8 人日 | 阻塞问题关闭，保留结果和包摘要 |

工程量合计约 46–91 人日，仅供排期；Linux 和 macOS 可分别达到发布门槛，
但每个平台都必须完成自身适用的功能、安全、供应链和最终回归。macOS
权限执行机制和 Apple 签名公证位于关键路径，不能用测试签名替代正式分发验收。

## 验收矩阵与交付物

| 类别 | 最低验收内容 | 记录的证据 |
| --- | --- | --- |
| 安装升级 | 全新安装、旧版本升级、保留配置和数据、卸载及回滚 | 系统版本、架构、包摘要、操作步骤和结果 |
| 日常使用 | 首次配置、桌面交互、项目与会话、流式输出、取消和重启恢复 | 功能结果、失败日志及问题编号 |
| 权限安全 | 合法操作、拒绝、过期、重放、符号链接替换、越权和审计 | 用例、运行身份、预期与实际结果及安全评审 |
| 网络设备 | Android 绑定配对、直连和中继、断网及恢复 | 设备和网络环境、复现步骤与结果 |
| 稳定性 | 自启动、进程崩溃、端口冲突、磁盘空间不足与恢复 | 故障注入和恢复结果 |
| 供应链 | 冻结源码、依赖和第三方许可，签名、摘要与更新元数据 | 提交、构建记录、组件清单、校验和签名记录 |
| macOS 分发 | Developer ID 签名、公证、装订及干净机器 Gatekeeper | 签名身份、公证结果及实际打开结果 |

最终应交付：按平台区分的安装包和校验值、可复现的构建及发布说明、
第三方组件与许可清单、完整验收记录和已知问题、用户安装与卸载文档、
升级回滚步骤，以及经负责人签字确认的发布决策。真实账户、Android 设备、
物理 Linux 桌面和 Apple 开发者证书需在相关阶段准备；当前尚无 Apple
Developer ID 证书，因此 macOS 正式签名和公证尚不能完成。
