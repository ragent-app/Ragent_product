# Android 与 Windows 本地语音处理方案

## 核心体验

语音默认按聊天自动选择处理位置。聊天属于一台已开启 Whisper 的电脑时，Android 自动把该聊天的录音交给这台电脑识别；电脑上的 Whisper 正在启动时，等待它就绪。用户也可以在聊天页右上角三点菜单中，将该聊天固定到手机或任一已配对电脑。

Android 可以查看和管理每台已配对电脑的 Whisper。Windows 电脑尚未安装 Whisper 时，用户可以直接从 Android 发起安装。远程安装成功后，该电脑的 Whisper 默认启用并启动，所以这台电脑上的聊天会自动改由电脑处理。Windows Ragent 安装器首次安装时默认选择 Whisper；保留选项就安装并启用服务，用户可以取消。

识别结果只填入聊天输入框草稿。用户检查后自行发送；语音流程不自动发送消息。自动模式只使用本机或已配对电脑，不会把音频静默上传到云端。用户可以在语音处理设备中明确选择中央 Accounts 云端识别；该路线会把音频发送给 Ragent Accounts 和 OpenAI Transcription API，并在选择前说明第三方数据处理政策。

## 控制项与默认值

安装/启停和聊天路由是两个独立控制面。更改某台电脑的服务开关，不会覆盖聊天里保存的手动设备选择。

| 控制项 | 设置位置 | 作用范围 | 默认行为 |
| --- | --- | --- | --- |
| Android 本机语音识别 | Android 语音设置 | 当前手机 | 用户单独开启；系统不支持时显示不可用 |
| 某台电脑的 Whisper | Android 语音设置或该 Windows Ragent 设置 | 该电脑 | 新安装后默认启用；可停止服务但保留文件 |
| 当前聊天的语音处理设备 | 聊天页右上角三点菜单 | 当前聊天 | 自动优先使用当前聊天所属且已启用的电脑 |
| Accounts 云端识别 | Android 语音处理设备 | 当前聊天 | 不参与自动路由；用户主动选择并看到音频上传说明后使用 |

## Android 操作流程

### 管理手机和电脑

Android 语音设置提供手机本机识别开关，并逐台显示已配对电脑的操作系统、连接状态、Whisper 安装状态、服务开关、运行/就绪状态、操作进度和错误原因。

电脑状态需要清楚区分：离线、未安装、安装中、已安装但已关闭、启动中、就绪和错误。支持远程安装的 Windows Ragent 在未安装时显示“安装 Whisper”；其他平台可以显示状态，但不提供尚未实现的远程安装操作。

用户从手机发起安装后，可以看到下载、校验、安装、启动和就绪进度。成功状态表示服务已经就绪，而不只是安装文件已下载。用户可以从同一页面独立启停每台电脑的服务。关闭服务不会卸载 Whisper；重新开启后 Ragent 启动服务。

### 选择聊天的处理设备

聊天页右上角三点菜单增加“语音处理设备”，按聊天保存选择：

- **自动（默认）**：优先使用当前聊天所属电脑的已启用 Whisper；不可用时使用已开启且可用的 Android 本机识别。
- **此手机**：固定使用 Android 本机识别。若本机识别关闭或不可用，说明原因，不转交电脑或网络识别。
- **某台电脑**：固定使用所选配对电脑的 Whisper，可选择会话所属电脑或其他已配对电脑。电脑必须连接、已安装并启用 Whisper；不可用时提示用户，不暗中切换设备。
- **Accounts 云端识别**：固定把本次录音发给中央 Ragent Accounts，由 Accounts 持有的服务端 OpenAI API 密钥调用 `gpt-transcribe`。选择后在录音前展示上传及供应商数据政策说明；额度不足、未登录或服务关闭时提示原因，不回退到其他设备。识别完成后只写入草稿。

菜单、录音按钮和录音状态应标明实际路线，例如“自动 · 工作电脑”“工作电脑 · 正在启动”“此手机 · 不可用”。未安装 Whisper 的电脑不能作为识别目标；用户可从语音设置发起安装。

### 录音和草稿

用户开始录音后，Android 先解析当前聊天的有效路线，再采集音频。用户点停止时，电脑路线应先结束采音并完成音频上传和识别；识别处理中再次取消才中止请求。收到转写后只更新草稿，不触发发送。切换聊天时取消旧聊天的进行中录音，避免把结果写入错误会话。

## 自动路由规则

每次录音开始时按以下顺序决定路线：

1. 若聊天保存了手机或电脑的手动选择，只使用该设备。目标不可用时提示用户，不自动换路。
2. 若选择“自动”，读取当前聊天所属的 Ragent 电脑。该电脑上的 Whisper 已安装且启用时，优先选择电脑，即使 Android 本机识别也已开启。
3. Whisper 已启用但仍在启动或载入模型时，保持电脑路线并等待就绪，不立即回退到手机。
4. 当前会话电脑离线、未安装 Whisper 或服务已关闭时，回退到用户已开启且系统支持的 Android 本机识别。
5. 如果自动模式没有可用的本地路线，明确提示用户连接/启用电脑或打开手机识别；不上传录音、不改草稿。只有聊天明确选择了 Accounts 云端识别时，才上传音频。

路线一旦用于本次录音，识别期间若连接中断或服务报错，只报告失败并允许重试或由用户更改路由；不能把同一段音频悄悄交给另一台设备。切换聊天后，自动模式按新聊天所属电脑重新判断；手动选择保持到用户主动改选或恢复自动。

| 当前聊天及设备状态 | 自动模式行为 |
| --- | --- |
| 会话电脑 Whisper 已安装、启用且就绪 | 使用该电脑 |
| 会话电脑 Whisper 已启用但正在启动 | 等待该电脑就绪 |
| 会话电脑离线、未安装或服务关闭，手机识别已开启且可用 | 使用手机 |
| 电脑和手机都没有可用路线 | 提示如何恢复；不上传、不改草稿 |
| 自动模式没有本地路线但 Accounts 云端可用 | 仍提示恢复本地路线；不自动产生云端费用 |
| 用户明确选择 Accounts 云端识别 | 发送到中央 Accounts；验证配额并显示本月剩余额度；结果只写入草稿 |
| 云端结果不确定或请求超时 | 不重复提交同一请求；保留不确定额度并提示用户先查看用量 |
| 用户手动选了不可用设备 | 报告该设备不可用；不自动切换 |

## 识别语言与平台能力

语音识别语言是独立于 Android/Ragent 界面语言的设置。语言选择器提供 Auto 和随当前 pinned `whisper.cpp` 运行时打包的 100 个语言代码，可搜索本地名称和原生名称。手机 Whisper 的 Auto 让 Whisper 检测语种；显式选择时把 Whisper 语言代码传给 JNI。Windows Ragent 同样把该代码传给本机 Whisper，并在设置 API 中报告支持的代码。

Android 系统内置识别器不等同于 Whisper，也不保证支持 Whisper 的全部语种。它使用手机当前系统语种（Auto）或用户显式选择的语种；该语种必须由手机上的 on-device recognition provider 支持并安装语言包。无法使用时应显示不支持或缺少语言包的具体提示；安装 Ragent 多语言 Whisper 模型后才有一致的离线多语言路径。Whisper 目录包含某个语种，只表示模型接受该代码，不代表所有语种的识别质量相同。Accounts 云端路线不读取手机界面语言，省略供应商的 `language_code` 参数以启用自动语种识别。

Windows 语音路由接收 Android 录好的 WAV 并直接交给 Whisper；Windows 扬声器的静音状态不会影响这条识别路径。手机本地路线也使用手机麦克风，不依赖电脑的扬声器或麦克风。

## Whisper 安装与服务生命周期

### 从 Android 远程安装

用户在语音设置中对支持的未安装 Windows 电脑点击“安装 Whisper”。目标电脑上的 Ragent 执行安装并返回可轮询的操作 ID：

1. 使用现有配对认证和目标电脑授权确认用户可以管理该电脑。
2. 从固定清单下载固定版本的 Whisper 运行时和多语言基础模型，限制下载大小并校验 SHA-256；只解压许可清单中的文件。
3. 在 Ragent 管理目录暂存文件，通过原子切换激活。失败时清理暂存并回滚，不破坏已有版本；重复请求不得并发重复下载。
4. 安装成功后保存 `enabled=true` 并启动服务。服务就绪后才向 Android 报告成功。
5. Android 后续在该电脑会话中自动路由到 Whisper；用户也可从聊天菜单改用其他设备。

远程安装和启停都只能经已认证、已授权的 Ragent 连接执行。Android 不直连 Whisper 端口，不传 shell 命令、脚本、任意下载地址或自定义路径。

### Windows Ragent 安装、升级和运行

- **首次安装 Ragent**：安装器默认勾选 Whisper 运行时和多语言基础模型。用户保留默认项时，安装后保存为启用状态并启动语音识别服务；用户取消时不安装、不启动。
- **升级时尚未安装 Whisper**：显示默认勾选的 Whisper 加装项。用户接受后安装、启用并启动；取消后维持未安装。
- **升级时已经安装 Whisper**：保留文件和服务偏好。用户此前关闭服务时，升级或重启不得擅自重新启用。
- **服务运行期间**：Ragent 只在 Whisper 已安装且启用时运行识别服务。启用状态随 Ragent 启动；关闭时停止服务但保留文件。用户可从 Windows Ragent 设置或 Android 分别管理对应电脑的开关。

默认把运行时、模型和安装暂存放在 Ragent 受保护的本地配置目录。Windows 管理员可以通过 `HKLM\Software\AgentoC\LocalVoiceSettings\RuntimeDirectory` 指定另一块本地磁盘；目录仅允许 Ragent ControlPlane 服务身份、SYSTEM 和管理员写入。用户语音偏好保存在独立的受保护配置目录。

## 音频路径、接口与安全边界

电脑路线：Android 采集单声道 16 kHz WAV，限制音频时长和大小，通过现有认证连接发送到所选 Ragent；Ragent 将音频交给只监听 `127.0.0.1` 的 Whisper，再将文字返回 Android。选择另一台电脑时，必须使用那台电脑自己的已认证连接。

手机路线：音频交给 Android 本机识别器，并禁用网络回退。云端路线：Android 将 0.5–20 秒的单声道 16 kHz PCM16 WAV 直接通过 Accounts API 上传到中央 Accounts 服务；服务核验 RAC 账号设备凭据和 entitlement 后调用 OpenAI Transcription API，再把转写返回 Android。API 密钥只在中央服务受保护的环境文件中。云端路线只在用户主动选择时使用。三种路线都只把转写写入草稿，不自动发送。

Ragent 接口保持窄范围：

- `GET /api/local-voice-settings`：返回 Whisper 安装、启用、运行、就绪、安装中和是否可安装状态，以及 API 版本和支持的语种代码。
- `PATCH /api/local-voice-settings`：仅接受 `{ "enabled": true|false }`，启停已安装服务。
- `POST /api/local-voice-install`：仅接受 `{}`，发起固定的 Windows Whisper 安装并返回操作 ID。
- `GET /api/local-voice-install/:operationId`：查询安装进度和结果。
- `POST /api/local-voice-recognition`：接收大小受限且通过格式检查的 WAV 和可选语种代码；仅在 Whisper 已启用时识别并返回文字。

旧版配对电脑没有 `supportedLanguages` 时，Android 只允许 Auto 语种并提示用户更新电脑后再使用显式语种。

以上接口复用现有 Ragent 配对认证和电脑授权；Whisper 服务端口不开放到局域网或公网。

## 验收标准

| 验收场景 | 预期结果 |
| --- | --- |
| Android 对未安装的 Windows Ragent 发起 Whisper 安装 | 目标电脑验证并安装固定载荷，默认启用、启动；就绪后 Android 显示成功 |
| Whisper 刚从 Android 或 Windows 安装器装好 | 服务默认启用；该电脑所属聊天的自动路线使用电脑 Whisper |
| 当前会话电脑 Whisper 已就绪，手机识别也已开启 | 自动使用会话电脑 |
| 当前会话电脑 Whisper 已启用但尚未就绪 | 等待该电脑，不改用手机 |
| 当前会话电脑离线、未安装或已关闭 Whisper | 自动回退到已开启且可用的手机识别；否则说明无法识别 |
| 用户从聊天三点菜单手动选手机或电脑 | 选择仅作用于当前聊天并持久保存；目标不可用时提示，不暗中改路由 |
| 用户关闭电脑 Whisper | 停止服务、保留安装文件；自动模式按规则转用手机 |
| Ragent 升级前用户已关闭 Whisper | 升级和重启后仍保持关闭 |
| 识别时连接断开或服务报错 | 当前识别失败，可重试或手动改路由；不静默转发到其他设备 |
| 识别成功 | 转写只进入当前聊天草稿；不自动发送 |
| 手机和会话电脑都没有可用识别路线 | 不上传音频、不改草稿，提示可操作的恢复方式 |

## 当前实现与验证进度

主线已包含 Android 本机识别开关、逐台电脑的 Whisper 状态与启停、手机发起 Windows 远程安装、聊天级路由和三点菜单、Windows 安装器默认安装/加装选项、载荷校验与失败回滚。电脑路线停止录音后继续上传转写的协程取消问题已修复；app 单测覆盖录音停止和转写处理。Whisper 返回 `[BLANK_AUDIO]` 或 `[ Silence ]` 时，Android 不把静音占位符加入草稿，而是提示用户重试。

Windows Ragent 0.0.42 已在测试机升级；正式命名的 Windows x64 setup EXE 已构建、校验并通过静默安装验收。测试机三项服务正常，Whisper 进程数为 1，Android 显示电脑语音服务就绪。Whisper 本地接口的合成 WAV 测试返回非空文字。

多语种扩展验收（2026-11-08）：共享目录与 pinned Whisper 原生目录一致，包含 100 个语言代码；Android 搜索选择器可选择全部代码，旧版电脑只广告 Auto 时会阻止不兼容的显式语言请求。Android 本地错误提示和新选择器文案覆盖英语、简中、繁中、日语、韩语、法语、西语。Honor MTN-AN80 / Android 16 上，native/JSON 目录一致性测试和 7 种界面语言资源测试通过；手机 Whisper 自动检测的预录样本测试通过英语、简中、繁中、日语、韩语、法语和西语；显式 `ko` 韩语预录样本测试通过。识别目录覆盖不表示每种语言有相同精度：样本结果有措辞误差，尤其短西语样本，仍应避免宣传“所有语言准确率一致”。

电脑扬声器到 Honor 麦克风的回环样本测试未通过：Windows 默认 Realtek 输出静音、音量 51%；临时解除后 Honor 只回传 `(라이브)`，因此这项电脑扬声器测试不算通过。随后在 Honor 上通过 `MediaPlayer` 从手机扬声器播放同一韩语样本，同时经应用的 `LocalVoiceController`、手机 `AudioRecord` 和 Whisper 回到草稿回调；显式 `ko` 识别到预期词 `한국어`，Android 设备测试 62.639 秒通过。测试会在原媒体音量为 0 时临时调到中档并恢复；本次验收后系统音量读数为 5。此测试验证了 Honor 上真实扬声器到麦克风的声学采集与识别链路，语音来源是预录样本，仍需避免把它描述成用户现场口述。

Windows 本机识别也完成真实运行时验收：用仓库 pinned 的 whisper.cpp v1.9.5 x64 运行时和 SHA-256 已验证的 `ggml-base-q5_1.bin` 启动隔离的 loopback Whisper HTTP 服务，经服务的 `/inference` 以显式 `ko` 识别同一 WAV，返回完整句子“안녕하세요. 휴대폰에서 한국어 음성 인식을 시험합니다.”。测试未重启或改写正在运行的 Ragent 服务，临时运行目录已删除。Windows 安装器的运行时固定包校验通过；本轮 Android 电脑端远程配对到 Windows 服务的端到端传输尚未在真实配对会话里复验，Node 路由/鉴权与语种传递测试覆盖了该接口边界。正常产品路线不依赖 Windows 扬声器输出。Node 本地语音测试 19 项通过；Android Workbench/app 单测和 debug APK/AndroidTest 构建通过。

中央 Accounts 云端识别是单独的显式路线，不改变上述本地自动路由。服务端代码和 Android 云端选项已加入主线实现；Accounts 新版本与迁移 042 部署后，可用 key 缺失状态验收关闭链路。公开隐私政策现已更新为 OpenAI Transcription API；真实供应商验收仍需安全配置 key，并按实际组织/项目设置完成 Google Play Data Safety 审核。未配置 key 时功能保持关闭。

补充的荣耀实机 QA 包验收（2026-11-08）：修正配对状态诊断测试的 JUnit 返回类型后，AndroidTest APK 构建成功；100 语种 native 目录一致性、7 种界面语言资源和 Honor 扬声器→麦克风→手机 Whisper→草稿回调测试再次通过（60.861 秒）。诊断测试只写汇总计数、不输出设备标识；独立 QA 包报告 `paired=0`，因此这轮无法用 QA 包验证手机到 Windows Ragent 的授权传输。本轮 ADB 安装目标仅为 `.opensource` QA 包，未对正式包执行安装命令。Windows 服务端语音识别与 Android 侧均已分别实测，但它们之间的真实配对链路仍未验收，不能据此宣称整条电脑识别路线已经通过。
