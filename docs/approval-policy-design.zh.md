# Ragent 审批决策策略设计

本文记录设计、当前源码落地及验收边界，更新于 2026-11-21；相关代码仍在调整，尚未部署。本文限定在审批决策策略，保留现有模式、默认值、provider 映射、API、界面、sandbox、runner 和 executor 的契约与行为。既有 Windows 与档位调整历史见 [审批链路调整方案](approval-gate-adjustment-plan.md)。

## 问题与现场证据

## 目标与边界

以可证明的操作效果、资源及范围、当前执行权限共同决定风险和执行需求。对完整理解的复合命令逐个检查子动作并取最严格结果。保留未知及硬风险的安全回退，减少已证明的普通只读操作被路径名称或复合形式单独放大的情况。决策、审计和现有卡片应消费同一最终原因与事实，避免解释与执行路径各自重算。

本设计不修改模式语义、默认值、provider 映射或现有能力授权语义。sandbox 和系统权限依然是独立边界，审批允许不代表系统一定允许执行。特权需求应由动作实际需要的能力及现有 executor 契约决定，不能仅由路径风险或 `danger` 推断可安全降权。现有实现存在 `danger` 与特权信号的耦合，解除该耦合须单独证明所有调用方和协议契约，本文不授权绕过现有门或改变执行器。

## 外部源码参照

以下为 2026-11-20 对固定提交的源码阅读，产品版本、权限模式和执行边界各不相同。语法解析负责提取可证明的结构，审批策略负责结合规则、请求来源、权限模式和执行环境作决定。解析成功不是自动授权，解析失败也不等于危险或必须提权。

- **Codex**：[`bash.rs`](https://github.com/openai/codex/blob/bb5b9c6240136de8ff4d30215e2341c44559aa04/codex-rs/shell-command/src/bash.rs) 使用 tree-sitter-bash，`try_parse_word_only_commands_sequence` 对可识别的命令序列提取参数，重定向、替换和控制流等超出该受限形式时返回未知。另有供其他用途的提取函数，其省略动态词或重定向的结果不能当作完整效果。[PowerShell 入口](https://github.com/openai/codex/blob/bb5b9c6240136de8ff4d30215e2341c44559aa04/codex-rs/shell-command/src/powershell.rs) 和[原生解析器适配](https://github.com/openai/codex/blob/bb5b9c6240136de8ff4d30215e2341c44559aa04/codex-rs/shell-command/src/command_safety/powershell_parser.rs) 将无法静态理解的语法保持不透明。[执行策略](https://github.com/openai/codex/blob/bb5b9c6240136de8ff4d30215e2341c44559aa04/codex-rs/core/src/exec_policy.rs) 再按匹配规则、未匹配回退、审批设置和运行环境决定允许、提示或禁止。其默认规则和不认识的程序的回退依具体配置而变，不能将解析器返回未知直接等同于某一种统一审批结果。
- **Gemini CLI**：[`shell-utils.ts`](https://github.com/google-gemini/gemini-cli/blob/d4cb1713fd7fc30f1c03f9ca7cbfed341c97dffd/packages/core/src/utils/shell-utils.ts) 用 tree-sitter-bash 遍历命令树，PowerShell 使用原生语言解析器，并单独记录重定向及子表达式。`splitCommands` 在解析失败或出错时返回空集合，空集合不是授权证明。重定向检测在解析不可用时使用保守的字符检查。[shell 工具](https://github.com/google-gemini/gemini-cli/blob/d4cb1713fd7fc30f1c03f9ca7cbfed341c97dffd/packages/core/src/tools/shell.ts) 的 `getConfirmationDetails` 使用这些结果构造展示。[策略引擎的 `checkShellCommand`](https://github.com/google-gemini/gemini-cli/blob/d4cb1713fd7fc30f1c03f9ca7cbfed341c97dffd/packages/core/src/policy/policy-engine.ts) 对子命令递归判断并聚合结果，还单独处理重定向。解析失败时保留明确拒绝，通常回退到配置默认决定，YOLO 模式另有针对参数限制的分支。该解析器不证明任意程序的完整文件副作用。
- **OpenCode**：固定提交的 [scanner](https://github.com/anomalyco/opencode/blob/e47d8feb50366e967a9c5d75699013b6459bf0dc/packages/core/src/shell/scan.ts) 使用内置扫描器，覆盖 Bash、Zsh、POSIX shell 和 PowerShell，并提取命令、嵌套结构和重定向资源。无法安全分析的语法返回 opaque，[`ShellParse.scan`](https://github.com/anomalyco/opencode/blob/e47d8feb50366e967a9c5d75699013b6459bf0dc/packages/core/src/shell/parse.ts) 将其转为错误。它尽力识别目录切换和可静态解析的路径，不是对任意程序文件访问的完整推断。[权限请求](https://github.com/anomalyco/opencode/blob/e47d8feb50366e967a9c5d75699013b6459bf0dc/packages/core/src/shell/permissions.ts) 分别检查工作目录、已提取目录及命令资源，[shell 工具](https://github.com/anomalyco/opencode/blob/e47d8feb50366e967a9c5d75699013b6459bf0dc/packages/core/src/tool/plugin/shell.ts) 在启动前逐项断言权限。

这些实现说明，命令拆分、重定向、实际 cwd 和路径范围需要分别提供证据。路径检查是某一时刻的观察，前序命令或其他进程可能在执行前改变目录、链接或目标。检查时的 cwd 也须属于实际执行环境，不能把远端路径交给本机文件系统验证。对跨命令状态变化、动态路径和未绑定对象身份的情况保留未知，不能把前一次检查视为执行时仍成立。

默认授权、不认识的程序和非沙箱中的常规操作是不同问题。默认授权取决于产品自身配置和权限模式，程序未被识别意味着效果证据不足，非沙箱操作仍受既有审批与系统权限约束。三家对未匹配规则、解析失败和不可交互情形的处理依各自契约而不同，不能直接移植其中任何回退去改变 Ragent 当前模式、默认值、provider 映射或 sandbox 语义。Claude 的规则及模式参考其[权限文档](https://code.claude.com/docs/en/permissions)和[自动模式说明](https://code.claude.com/docs/en/permission-modes#how-auto-mode-evaluates-actions)。
## 本次源码落地与验收状态

当前实现让 POSIX AST 保留 argv 参数边界，并分析受支持的多级管道、`&&`、`||` 和分号序列；复合动作继续汇总各子动作的决定，无法证明的语法或效果保留人工处理。Claude Bash 的受控路径通过 cwd guard 绑定实际 cwd，原始命令原样交回 provider 执行。普通同用户文件读取和浅层目录列表可在本机核实目标；工作区内受限的字面重定向按既有文件编辑档位处理。已有模式、阈值、权限接口、sandbox 和 executor 契约保留。native 请求的相对或缺省 cwd 目前尚不能绑定实际执行目录，缺少这一事实时不能据此自动放行。

阶段出口使用既有检查：Linux WSL 中 command-parser 73 项通过，Claude POSIX `rg`、真实 Linux shell 与回传检查通过；Windows PowerShell actions 和 Windows approval gate 检查通过；审批事件 16 项、sidecar 路由 8 项通过。真实 shell 检查曾因缺少 `seq` 被错误判为终止；生产 guard 统一修复后相应检查通过。现有 POSIX parser suite 在 Windows 上的 `/etc` 分类断言失败，在正确的 Linux 环境运行通过。上述证据覆盖所列检查，不证明所有 provider、平台或生产流量均已验收。

对两条历史请求只做结构静态对照，没有远端执行原命令。第一条涉及 provider 控制目录元数据、`~/` 与绝对 glob、丢弃 stderr 和三级管道。候选策略支持可证明的受保护元数据形态：仅含绝对锚定 glob、精确的 `2>/dev/null`、多组 `ls`、stdin 过滤和字面 `echo`；该形态仍须人工审批，并避免进入特权执行路径。原请求还包含尚未绑定 provider HOME 的 `~/`，因此整条历史请求仍保留原有审批和分流，不能声称已消除。第二条包含循环、变量和 glob，读取同用户 Claude 历史文件的元数据，仍需 review。没有 VPS 部署或生产审批频率数据，也不能从两条记录推导审批率。

文件系统核验是检查时的观察，不是执行时的快照：链接、目录或目标可在批准与执行间变化。Linux reviewer snapshot 的生命周期和认证限制仍是独立依赖；缺少可信事实或绑定时保留未知及现有模式回退。

## 事实契约

分析产生带来源、完整性及策略版本的不可变事实记录，再交给决策层。以下字段是拟议内部契约，具体表示须适配当前接口，不能假定已经存在。

| 维度 | 要求 |
| --- | --- |
| 请求身份 | provider、Run、请求或轮次标识、原始工具参数摘要、平台、实际 cwd 与可信来源，缺失即未知 |
| 语法 | shell 方言、解析器版本、完整性、节点和子动作边界，解析成功不等于语义已知 |
| 效果 | 每个子动作的读取、元数据枚举、写入、删除、进程执行、权限变化、网络及其他副作用，未知单独表示 |
| 资源 | 原始目标、解析后的规范路径、真实路径、所属范围、目标集合是否完整，记录符号链接及解析失败 |
| 数据流 | 管道、重定向、命令替换和输入输出关联，覆盖读取后外发及写入目标 |
| 权限 | 已证明的执行身份、现有 sandbox 与能力需求，未证明的能力为未知 |
| 依据 | 事实来源与可信度、规则版本、原因码及决定性子动作，避免把模型描述当作事实 |

目标规范化须以实际执行 cwd、用户身份及环境为准。glob、变量、链接、挂载、路径不存在和执行前资源变化都可能使目标集合不完整。分析不得执行原命令或展开任意代码来获取事实。无法证明绑定时回退现有未知流程。对批准到执行间可能发生的目标变化，应在执行边界重新核验可核验的身份、路径及能力约束，不能核验则不得依靠过期事实自动放行。

## 决策和优先级

1. 先验证请求身份、事实来源和完整性，并执行现有硬约束、明确拒绝与能力边界。低可信输入不能覆盖高可信限制。
2. 将每个可证明的子动作按效果、资源、范围及实际权限分类。只读、敏感读取、修改、外发及提权各自有规则，受保护资源的读取仍要单独判定敏感性。资源位于受保护根目录本身不是证明动作会修改该目录的证据。
3. 对所有子动作和重定向取现有决策语义中最严格的结果。任何硬拒绝保留拒绝，任何需要人工的动作保留人工，未知不能被其他已知安全动作抵消。无交互或 full-auto 的具体结果继续遵循当前模式。
4. 确定性规则不能完成判定时，只有满足下文边界的请求才可进入上下文复核。复核失败保持未知并走现有模式回退。
5. 在现有协议中一次性决定整个原始请求。禁止先执行安全子集、再询问剩余部分，也不把用户批准的一部分解释为对其他子动作的批准。

需要区分已知危险、已知普通及未知。未知包括不支持的语法、不可确定的目标或副作用、身份缺失、事实过期和分析器故障。语法未知不自动等于危险或特权需求，但也不能成为自动允许的依据。各分支保留具体的机器原因码、决定性事实及来源，最终原因由同一决策结果传递到审计和现有展示。迁移时保留已有原因码兼容，并明确记录原始分析原因与最终决策原因，避免丢失故障诊断。

现有门中 safe 与 conservative-auto、recommended 与 full-auto 分别共用自动放行阈值，不能自动放行时按各自模式回退。具体仍以现有分支和 provider 请求路径为准。[通用门](../chat/privileged-gate.mjs)、[sidecar](../chat/runner-sidecar.mjs)。

## 决策矩阵

下表表达目标契约，最终输出仍经现有模式映射，不能直接替代现有代码。

| 可证明事实 | 策略结果 | 约束 |
| --- | --- | --- |
| 存在硬拒绝或禁止能力 | deny | 优先于授权、其他子动作和 reviewer |
| 所有效果和目标完整，均命中现有可允许规则 | allow 候选 | 仍须通过能力、上下文和执行边界 |
| 已知动作要求人工且无硬拒绝 | ask | 无交互行为由现有模式决定 |
| 语法、目标、效果、身份或能力存在未决事实 | unknown | 仅符合边界时送 reviewer，否则按现有模式回退 |
| 只读与写入、外发或提权混合 | 按全部效果取最严格结果 | 数据流不明时为 unknown |
| 单次人工批准 | 仅绑定该请求的决定 | 不产生可复用授权或绕过 sandbox |

## 复合命令和只读范围

相同用户或文件所有权本身不能证明目标在授权和 sandbox 范围内。

扩展 POSIX AST 支持必须逐类证明语义，包括控制流、变量、glob、管道、重定向和嵌套结构。每种支持需限定静态可解析形式及其副作用，无法证明的部分维持未知。已识别程序仍需验证完整参数、隐式配置、输入来源和可执行文件身份，解释器、插件、外部命令调用及会执行回调的参数不可仅凭程序名称归为只读。分支即使运行时未选中，也应对所有可能执行的分支求最严格结果。循环次数、目标集合或数据流无界时不自动授权。

拟议只读类只覆盖可证明的列目录、元数据和内容读取等明确效果，并按工作区、用户目录、受保护控制数据、敏感文件及系统资源分别判定。元数据仍可能泄露名称和结构。跨用户目录、凭据、控制数据及权限不足的目标需要现有更严格规则，不因命令声称仅计数而自动允许。限制输入字节、AST 节点、子动作、展开目标、遍历深度和时间，达到任一上限即未知。具体阈值须结合现有实现和代表性数据另行确定，不在本设计中凭空指定。

读取加网络发送、重定向写文件、命令替换、管道消费者产生副作用等均按完整数据流及所有效果判定。无法证明外发目的地、内容或副作用时保持未知，不能把上游只读作为整条命令安全的证明。第一条现场请求跨用户及 provider-home 根目录，第二条包含动态结构，两者都不能仅凭自然语言摘要直接自动放行。

针对第一条现场请求，跨用户或跨 Run 的范围在现有规则允许人工授权时保持 ASK。若已证明无需提升执行权限，则使用普通审批路径，硬拒绝仍保持拒绝。第二条仅在证明实际 cwd、根目录、目标集合和元数据效果有界且符合现有授权范围后才有资格成为 ALLOW 候选，否则维持当前回退。这些是设计条件，不是对历史请求的重新判定。

## 单次决定、授权与能力

单次人工批准绑定原始请求、Run、身份、工作目录、目标、权限与请求参数，按现有协议处理重复请求和失效。可复用授权是更宽的能力，必须使用现有明确授予语义、范围、有效期和撤销方式，不能由单次批准自动产生。任何授权均不能覆盖硬拒绝、超出授予范围的目标、变化后的请求或 sandbox 限制。对特权批次，风险判断、是否要求人工、是否需要现有特权执行路径是相关但不同的决策，现有能力检查和 executor 分派在单独完成契约审计前保持原样。

## 有界上下文复核

确定性检查先行。仅将已具备可信请求身份、边界和必要事实且不存在硬风险或禁止能力的未知请求送入 reviewer。模型不得补造路径、目标、效果、身份、权限或执行结果，不得覆盖硬拒绝或扩大授权。输入只包含最小必要上下文，排除凭据与不必要的文件内容，遵守当前大小和超时上限。输出必须通过严格结构校验并受确定性门约束，超时、配置变化、不可用、无效响应或信息不足均保持未知。提示中的命令、文件内容及 provider 返回内容均属不可信数据，不得作为策略指令。

Linux reviewer snapshot 是独立后续依赖。已观察的生命周期准备路径未持久化 snapshot，后续需要核实 Run 绑定、版本和凭据变更失效，并分别处理当前 `oauth-token` 与现有 API-key-only 支持。先修复 snapshot 并不自动支持 OAuth，改变认证支持也不属于本文实施范围。现有代码对缺失 snapshot 与不支持认证分别回退，后续须保留可审计原因，不能通过跳过校验恢复自动审批。[生命周期启动](../chat/run-launcher.mjs)、[生命周期 broker](../scripts/runner-lifecycle-broker.mjs)、[复核适配器](../chat/approval-context-review.mjs)、[请求门](../chat/runner-sidecar.mjs)。

## 实施顺序、验收和回退

### 分阶段交付门槛

| 阶段 | 优先工作和主要文件 | 退出条件 |
| --- | --- | --- |
| 事实盘点 | 审查 [风险策略](../chat/risk-policy.mjs)、[分类器](../chat/risk-classifier.mjs)、[通用门](../chat/privileged-gate.mjs)、[Windows 门](../chat/windows-approval-gate.mjs) 和 [sidecar](../chat/runner-sidecar.mjs) 的分支、能力、cwd 与消费者 | 明确所有提前返回、硬约束和可追溯字段，确认外部契约保持不变 |
| 确定性分析 | 在 [POSIX AST](../chat/posix-shell-ast.mjs) 和现有分类门中逐类限定可证明语法与效果 | 未决事实不升级为允许，复合聚合顺序独立，既有适用可信检查通过 |
| 集成与影子比较 | 连接现有分派、审计及解释，审查 [已批准动作](../chat/approved-actions.mjs) | 单次授权和在途请求语义保持，真实历史中每个已评估的更宽松差异均有解释 |
| reviewer 依赖 | 独立调查 [启动器](../chat/run-launcher.mjs) 和 [reviewer](../chat/approval-context-review.mjs) | snapshot 生命周期和认证限制有可信证据，失败继续回退，OAuth 支持另行确定 |
| 发布准备 | 使用既有适用检查和代表性观察，准备关闭开关及基线回退 | 平台与 provider 的缺口明确，送达与执行证据分层，回退和在途对账可行 |



先盘点所有 `tier`、`needsPrivilegedExecution`、原因码、授权和展示消费方，确定不改变外部契约的内部事实及决策接口。然后增量扩展能完整证明的 AST 和动作规则，保持旧规则回退。最后接通统一最终结果与现有解释，独立处理 reviewer snapshot 依赖。每一步审查直接依赖和并发请求、幂等及执行边界，默认关闭未完成规则。

验收使用已有可信回归和代表性业务数据，检查已知安全、硬风险、未知、复合动作、路径与身份变化、复核不可用、单次批准和现有模式映射。对两条现场记录仅做离线静态分析与已有记录对照，不重新执行原 shell，不构造预期结果充当业务证据。记录规则版本、实际请求来源、最终原因、是否进入人工与实际执行权限，检查同一决定在审计和卡片中的一致性。Linux 原生链路、真实 provider 认证与批准到执行间的变化需分别有证据，缺少证据时明确保留未验证状态。新增测试或测试基础设施须先取得用户许可。

上线前通过既有策略版本或部署机制准备可关闭的新规则及回退到现有决策路径的机制，内部灰度可选，不新增用户设置，保留原有硬门与授权记录。出现错误放行、原因不一致、特权分派变化或无法解释的未知增长时停用新规则并回退，保存脱敏证据与策略版本后排查。方案效果只能由实施后的可信观测证明；当前已有能力和未验证边界见“本次源码落地与验收状态”。

## 集成审计重点

现有路径分类包含词法路径处理，范围标签与执行范围清单的 digest 是准入上下文，不是目标对象在执行时不变的证明。事实应保留原始 argv 的参数边界和实际执行形态，不能通过拼接字符串消除包含空白、Unicode 或特殊字符的参数区别。链接、别名、程序身份与对象变化无法可靠绑定时，保留未知。快照本身不能在现有 sandbox 和 executor 约束下授权不可验证的可变目标。

现有通用门和 Windows 门存在提前返回及特殊分支，受管 learning profile 写入也有前置例外。未来集成须保证任何分支均不能覆盖更严格的风险、能力扩张或上下文约束。POSIX 子命令聚合须显式保证 deny 优先于 ask，结果不依赖遍历顺序，不能仅凭 AST 完整把未决效果提升为允许。现有代码使用首个 ask 或 deny，当前依赖分类结果的构成。以上是需要持续审查的集成边界；当前 POSIX 聚合已显式优先保留 deny，尚未证明存在可利用绕过。[通用门](../chat/privileged-gate.mjs)、[Windows 门](../chat/windows-approval-gate.mjs)、[分派](../chat/runner-sidecar.mjs)。

Windows 与 POSIX 当前使用的 cwd 上下文和文件变更来源不同。统一事实契约时须保留现有平台证明，不得把会话 cwd 当作未经证明的实际执行 cwd，也不得因缺失事实降低安全门槛。Windows 的后续工作应先核对现有证明和文件变更关联。

## 观测口径

Ragent 发起自动响应的尝试、传输写入成功、provider 确认接收以及动作最终结果是四个不同事件。缺少后续事件时只报告最后有证据的一层。

后续评估应固定提交、策略版本、平台、provider、模式、配置与观察窗口。只有现成记录支持时才对同一真实请求离线比较基线与候选决定，记录原因和缺失事实，绝不执行候选决定。上游没有发出审批请求的动作可能无法观察，Codex 的允许规则也可能不产生审批事件，因此没有卡片不能证明 Ragent 自动批准。已拦截样本不能作为所有动作的分母。历史 Windows 数据及其模拟模型、身份和网络夹具限制见既有方案。

分层记录可观察动作、provider 发出请求、Ragent 意图决定、复核送达、用户决定、provider 确认接收及实际执行或外部回执，按请求身份去重并报告关联缺失。人工超时、离线、取消、拒绝和未响应分别统计。当前 Codex 通用自动允许路径记录 `autoApproved` 与响应状态时未检查写入返回值，意图指标不能单独证明 provider 已接收，诊断改进留待另行确定范围。对敏感或不可逆动作、授权范围扩大、事实缺失或陈旧、候选更宽松和关联不明的记录逐项人工复核，报告分母、来源、未知量及平台分层。

在同一批可关联请求中分别报告呈现给用户数除以上游审批请求数，以及因候选策略转为自动放行的可评估数除以该批可评估请求数。未知、送达失败及结果无法关联分别报告，不预设数值目标。

按实际改动选择已有可信检查，例如 [风险策略](../tests/test-risk-policy.mjs)、[风险分类](../tests/test-risk-classifier.mjs)、[审批韧性](../tests/test-approval-resilience.mjs)、[Codex 幂等](../tests/test-codex-approval-idempotency.mjs)、[事件风险契约](../tests/test-approval-event-risk-contract.mjs) 和 [Windows sidecar](../tests/test-windows-sidecar-approval-live.mjs)。此处列出可按改动选择的候选，不表示全部适用于每次变更；本次已运行的检查见“本次源码落地与验收状态”。回退时保留在途审批状态和对账记录，已经发送或执行的动作不能称为已撤销。

候选策略的影子比较不参与执行决定，已在途请求继续使用产生请求时的生产决定，不进行双执行。可复用既有审计或 OPA 比较概念，但须覆盖共用解析器、效果检查和最终门禁，现有 [OPA 适配器](../chat/risk-policy-adapter.mjs) 的 tier 比较不能视为最终决定的完整对照。历史记录缺少执行绑定时标为无法评估，不从当前文件系统重建历史目标。首批发布评估应逐项解释已评估历史证据中从 ASK 或 DENY 变为 ALLOW 的差异。仅有投影或传输日志时不声称执行结果。
