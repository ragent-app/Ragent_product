# Factory Runtime 剩余工作与验收清单

更新：2026-11-14；整理基线：`main`、`50e97a13`。本文件只组织后续工作，不表示这些工作已完成，也不授权实际运行、发布或新增测试。实现与现有证据的详细状态见 [实施状态](implementation-status.zh.md)；原始范围及退出标准以 [总方案](00-master-plan.zh.md) 和 [阶段 0](phase-0-baseline.zh.md)、[阶段 1](phase-1-work-graph.zh.md)、[阶段 2](phase-2-execution.zh.md)、[阶段 3](phase-3-team-control.zh.md)、[阶段 4](phase-4-delivery.zh.md)、[阶段 5](phase-5-rollout.zh.md) 为准，本文不缩减它们。

共享后台 broker 是保留设计：继续以任务工作目录、契约、有效授权、执行代次和结果事实约束执行；不把每任务替换为独立后台进程或另建 OS sandbox 当作默认前提。平台或 provider 实际能力不足时，要明确拒绝或标明受限，不能由配置或编译通过推断运行能力。

## A. 仍缺实现或需要完善的功能

以下是源码层面的后续工作；每项的完成仍须按下一节取得相应环境证据。

本轮已提交的部分：远端委派不含收件箱的有界任务摘要（`e6a39b38`）；owner 针对单任务明确固定已有项目事实（`e36fe334` 与 `0c9719da`）；owner 显式逾期提醒（`a6ee4851`）和 Run 范围结构化阻塞提案及 owner 处置源码（`233094db`）；本地组织范围状态观测（`cf722af1`）。这些不代表完整长期知识、自动升级、跨实例知识委派或真实运行验收已完成。

- [ ] **执行和外部副作用的恢复/补偿（阶段 2、4、5）。** 补齐从 claim、派发受理、Run/Packet、候选、集成到外部操作的可追溯对账、幂等处置和必要人工入口。**验收：**各状态能定位原意图与实际事实；只有有足够终止、隔离或结果证据才恢复对应动作；证据不足时保持 unknown/blocked 并给出可执行的人工对账路径，不以 TTL 推断任务停止，也不要求所有未知外部结果都自动恢复。
- [ ] **GitHub 发布中断恢复（阶段 4）。** 现有 opt-in provider 已固定仓库、tag、签名工作流、已集成 commit 和资产摘要；仅已捕获错误进入 unknown 且资产完整的 draft 支持显式 finalize。进程崩溃停在 `sending`/`recovering` 时，尚缺可靠的发布子进程完成事实和安全恢复入口。**验收：**对该状态能在可靠证据支持下安全对账并明确允许的后续处置；无法证明停止或外部结果时继续阻断，不靠父进程消失、TTL 或共享 broker 状态猜测。空/部分 draft 不自动补传、不覆盖已有资产是当前保守策略，无需为完成清单取消。
- [ ] **长期团队知识与远端 handoff（阶段 3）。** 本地已有 node/工作项范围上下文；远端委派已有不含收件箱的有界摘要，owner 可为单个任务固定已有项目事实。远端携带知识引用目前拒绝，完整长期项目知识与预算等事实仍有缺口。**验收：**授权范围内的合同、候选、关键决定、失败和未答事项可追溯；来源变化标 stale，截断明确为 `unknown_truncated`，不把摘要当授权或验收；换人/模型保留历史，远端按明确授权范围接入且不泄露其他节点消息。已冻结输入不改写；发送前检查不能声称与跨库/外部发送原子。
- [ ] **消息与指挥能力的剩余范围（阶段 3）。** 当前岗位消息入口支持 information/required_response 和 owner 显式逾期提醒；将已有 consultation、结构化阻塞提案与阶段方案的其余升级处理形成受控闭环，并核实控制生效回执与各 runtime 实际支持；不支持的 steering 路径保持明确 unsupported。**验收：**请求、送达、协议消费/ack、答复和工作图变更分别可查询；ack 不等于答复，必要答复超时不视作同意，实际控制效果有相应回执，权限或能力不足不伪称生效。
- [ ] **一致性检查点、监控和能力矩阵（阶段 5）。** 补齐数据库、Run 文件、产物及已发生外部效果之间可解释的一致检查点，以及面向部署的监控与逐平台/运行时能力状态。**验收：**可列出活动/未知操作、数据与事件水位、来源及缺失事实；矩阵分别标记源码、配置、实际验证和不支持，监控覆盖重复派发、权限拒绝、无法取消、预算滞后和恢复卡住，不凭空设 SLA。
- [ ] **历史映射及兼容退出（阶段 1、5）。** 扩充可可靠关联的历史对账和差异处理，明确旧入口何时可安全退役。**验收：**只映射有证据的旧 Task/Attempt/Run/Packet；缺组织、契约或证据的历史保持未知/人工确认，shadow 不派发或改写历史。全量强迁移和删除旧 Collaboration 入口不是首版硬门槛；只有无活动引用、历史可读且回退窗口结束后才另行决定退役。
- [ ] **长期交付证据与其他渠道（阶段 4）。** 完善检查、审批、构建来源、产物和外部结果的索引、保留及失效规则；仅在项目实际选用时实现 PR 创建、更新、合并及未知结果查询，或接入其他正式发布渠道。**验收：**每个实际外部动作分别有授权、幂等身份、固定输入和真实结果；活跃/待决证据受保护，历史紧凑索引保留。直接 Git commit 路径仍可使用，PR 是可选渠道，不是所有交付的先决条件。

预算缺可信 provider usage 时继续保留预留，不把它记为零消费；需要完善的是可追溯的后续结算或人工处置，并非取消这一保守策略。各平台和 provider 按声明范围支持，不要求未经选择的全部 provider 都实现。

## B. 已有源码但缺真实验收证据

- [ ] **基础与图（阶段 0–1）。** 用已授权实例确认返工 lineage、Session/Grant、候选先冻结、加法迁移及旧版本读取；验证持久目标/契约/依赖、单一写入口、CAS/幂等、暂停取消和旧代次失效。**验收：**实际重取和版本/回执与权威事实一致；legacy/shadow/active 唯一所有权明确，shadow 不派发，不抢走旧任务。
- [ ] **真实执行、控制和预算（阶段 2）。** 在步骤 2 的真实任务中记录准入与受限工作目录、依赖里程碑、候选和验收；按实际能力验证暂停/取消、撤权、晚到事件、预算预留/可信结算和恢复。**验收：**不越权、不重复派发或重复记账，未知用量/副作用仍被保留；独立审查不写目标，未验收候选不自动回写。共享 broker 的任务级行为须有实际事实，不能用进程存在或 lease 过期替代。
- [ ] **团队与客户端（阶段 3）。** 验证真实组织的换会话、换人、节点消息、回复、生命周期、Web 与 Android；现有 Android 已接任务与消息入口；覆盖断线后权威重取及旧客户端兼容。**验收：**同一任务事实、commandId 和生效回执跨客户端一致；真实设备/连接证据与包含 Resume 的 `a6ee4851` Kotlin 编译证据分开；普通聊天和受管输入边界保持兼容。
- [ ] **Android 离线投影（阶段 3）。** `cfc20b5d` 提供按已验证身份分区的加密、有界只读快照和缓存时间，离线不排队命令；该增量尚未编译或真机验证。**验收：**验证离线来源与时间、撤权清理、重新连接时权威重取及无重复命令；能力不具备时明确提示。
- [ ] **工作流、候选与交付（阶段 4）。** 在真实项目验证固定版本模板、独立审查、已有可信检查、单候选与组合候选、目标变更/证据失效、真实 Git 集成和候选包。**验收：**实现、审查、检查、集成和包的内容身份可追踪；组合只采纳适用于组合的证据；契约修改或返工不复用旧 passed；发布请求、授权、实际结果分别显示。
- [ ] **已授权的 GitHub 渠道（阶段 4–5，适用时）。** 对明确配置仓库和签名工作流、已有可信 CI attestation 与已存在目标 tag 的实际项目，验证证明、draft、单资产摘要、发布结果和查询/恢复边界。**验收：**记录服务器核验的 source commit、资产 digest、授权与远端实际结果；构建证明或渠道缺失保持受阻，未获授权不发布。历史发布事实与当前远端观察分开，外部并发变更不声称跨 API 原子。
- [ ] **备份、迁移、shadow 和回退（阶段 5）。** 在授权隔离范围验证已有备份工具、恢复、加法迁移、分页影子对账与显式 workspace 退休。**验收：**数据库/WAL、必要 Run 与产物索引、事件水位和外部副作用之间的一致性及遗漏被如实记录；恢复后事实可追溯，退休保留必要证据，不删除活动引用或其他任务数据。
- [ ] **持续运行、跨 Harness 与平台（阶段 5）。** 在声明的平台范围内完成实际退出/重启、真实多客户端和同一 Work Graph 中不同 Harness 的协作。**验收：**持久事实、当前授权和命令回执在重启后可核对；不同 Harness 在同一图中交换可验证候选/证据；Windows、Linux、macOS、Android 及远程能力分别标明实际支持或未验证，不以单聊、跨平台编译或另一个平台结果外推。

## C. 全阶段最终验收与证据保留

原阶段 5 标准不变：团队和任务在退出与实际重启后仍有完整事实；用户能真实指挥并区分请求与生效；多 Harness 在同一图按契约交付；换人、重试、返工和恢复保留历史且不重复造成副作用；验收、候选、集成、包和审批有真实证据；已有用户路径兼容且回退不丢事实。仅部分平台/模式达到时，只能声明该范围，不把全部阶段标为已验收。

每次实际验收保留紧凑索引：源码/包身份、平台与 runtime、业务输入和 contractRevision、organization/workItem/epoch/Attempt/Run、候选/集成/产物摘要、operation/授权/实际结果、已有检查或人工验收、未验证项及恢复风险。生产部署、外部发布、服务重启或付费执行须在各自明确授权和可恢复范围内进行；不为补证据自行创建测试、mock、脚本或虚构业务数据。
