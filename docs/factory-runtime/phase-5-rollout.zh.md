# 阶段 5：渐进迁移、真实项目验收与发布

状态：方案部分已落地，缺项与验证状态见 [实施状态](implementation-status.zh.md)。日期：2026-11-13。上位：[总方案](00-master-plan.zh.md)。前置：[阶段 0–4](00-master-plan.zh.md#14-分阶段边界与完成条件) 对目标发布范围的能力已实现。

## 1. 目标与边界

在不破坏现有用户会话、组织、历史任务和并行工程工作的前提下，确认 Factory 在实际支持的平台与真实项目上可用，并完成可回退的渐进启用。

本阶段不是扩大测试数量。真实运行结果是独立证据，不能继承旧报告或用新构造的 mock 成功替代。未达到的支持平台明确延期或限制能力，不能用跨平台编译通过代替运行验收。

## 2. 发布前输入

- 明确的候选源码身份：HEAD、相关未提交补丁摘要、安装包来源和 digest。实际发布应来自已固定的候选，不能从多人活动工作树直接构建未知内容。
- 各阶段完成项、未完成项、禁用能力及真实证据清单。
- 实际项目的授权需求和既有验收标准；选范围有限、可隔离且能判断正确性的工作。
- 原实例身份、owner/授权、目标数据位置、已安装版本和活跃任务清单；不读取或打印无关凭据。
- Windows G: 容量和所有工作产物路径；不为三平台验证提前下载整套新运行时。

## 3. 工作包

### P5-01：能力支持矩阵

逐项记录源码具备、环境可用、实测通过、受限或未验证，不只写一个“平台支持=true”。

| 环境 | 必须分别记录的能力 | 当前方案基线 |
| --- | --- | --- |
| Windows 主机 | 查看/控制、Writer 隔离、候选、集成、取消、恢复、只读审查 | 静态代码已读；真实运行未验证；内置认证只读不能默认成立 |
| Linux 主机 | 上述能力及 bubblewrap 实际隔离 | 有内置认证路径；具体安装/服务/Harness 未验证 |
| macOS 主机 | 查看/控制、Writer 隔离、候选、集成、取消、恢复、只读审查 | 不能由 Linux/Windows 结果外推 |
| Android 客户端 | API 包络、任务/组织显示、命令回执、断线重连、证据访问 | 已有组织模块，实际接线/真机仍需验证 |
| 远程控制 | 客户端身份、目标授权、网络断开后的事实一致性 | 复用现有远程链，不预设跨实例调度已实现 |

按 runtime family 而不是品牌列能力。Codex 的不同传输、Claude 的停止后续接等语义独立记录。可首先发布“Windows/Android 控制已验证 Linux 工厂”，但必须清楚声明执行位置和缺失的本地能力。

### P5-02：一致备份和加法迁移

停新准入或进入一致性检查点，确认活动写入与待决外部操作；通过可信备份方式保存 collaborations.sqlite、project-workflow.db、runtime-coordination.db 及必要 Run/产物清单。SQLite WAL 不能只复制主文件而忽略未 checkpoint 的内容。

记录 schema version、数据身份、事件水位和候选引用。备份不复制无关历史大资产，不泄露账号凭据；所有本地快照位于 G:/AgentoC。

迁移只新增兼容字段/表，不原地把全部旧任务改为 Factory 完成状态。先导入历史关联和只读 shadow，列出缺失契约/证据/根会话的记录。缺数据项保持历史/待确认，不补造验收结论。

### P5-03：shadow 对账

在现有实例获授权的隔离范围，对照旧 Task/Attempt/Run/Packet 与新投影的 ID、终态、事件和关联。shadow 不创建 Run、不发消息、不改旧任务终态、不触发计费。

差异分类为映射错误、旧事实不完整、晚到事件、版本不兼容或真正执行缺陷。逐项纠正映射或记录限制，不为使计数一致而改写业务历史。

### P5-04：小范围 active

只选择新建且显式 Factory-owned 的真实任务，有限并发、有限预算、固定执行平台。旧 Collaboration 自然收尾，默认不接管活动旧工作。

复用用户真实项目已有标准，记录任务输入来源、契约、实际运行及成果。若测试/构建缺可靠 oracle，则报告未验证；不临时创造一组用来证明系统正确的玩具任务。

监控重复派发、未知执行、错误完成、权限拒绝、无法取消、预算滞后、恢复卡住和投影差异。阈值按实际服务要求设定，不在缺负载数据时臆造 SLA。

### P5-05：持续性与控制证据

以下是发布所需事实范围，具体如何取得优先采用既有可信检查或已授权真实操作，不能据此自动新增故障注入脚本。

- 客户端退出后任务仍由服务端推进；重连能从权威事实恢复视图。
- 实际服务重启后，持久团队、任务、候选、审批和预算仍可关联，执行是否续跑如实记录。
- 请求重试/响应丢失时不会重复创建有效执行或重复集成；未知副作用被阻塞而非猜测成功。
- 运行中改变优先级、范围、负责人时版本与回执一致；旧结果不能覆盖新任务。
- 权限撤销、环境能力不满足和预算耗尽时不启动越权工作。
- 审查、集成、候选包和发布审批所绑定内容一致。

涉及服务重启或故障操作时先确认该实例已有授权及可恢复条件。不能为了验证而中断现有生产任务；可以在已获授权的隔离实例取得适用证据，并准确标明范围。

### P5-06：实际客户端与多 Harness

在已连接且获授权的 Android 真机和 Web 查看同一任务，确认组织/任务详情、待批动作、消息、断线提示和生效回执。截图只能证明界面当时显示，不证明后端副作用；需要 operation/result 关联。

真实 Codex / Claude 执行分别记录实际 runtime family、provider/model、有效权限、输入契约和 Run ID。不能因两种模型分别能单聊就宣称跨 Harness 团队已验收；必须在同一 Work Graph 中交换可验证候选/证据。

### P5-07：发布与兼容退出

达到当前声明范围后，按现有发布授权与渠道流程发布候选；保留清晰已知限制。开关组合以实际有效能力为准，客户端不展示未发布动作。

只有确认无活动引用、历史可读且回退窗口结束后，才考虑退役重复旧入口。第一版不强制删除旧 Collaboration 功能。旧接口的移除是单独兼容决策，不能用 schema 增加顺带取消用户原工作流。

## 4. 验收证据包

每次实际验收保留一个紧凑索引，包含：

| 字段 | 用途 |
| --- | --- |
| sourceIdentity / packageDigest | 确认验证了哪份代码和安装包 |
| platform / runtimeFamily / effectiveCapabilities | 确认真实支持范围 |
| businessInputRef / contractRevision | 确认需求及正确性依据来自哪里 |
| organizationId / workItemId / executionEpoch / attemptId / runId | 联结领域与执行事实 |
| candidateDigest / integratedCommit / artifactDigest | 联结验收、集成和产物 |
| operationId / approvalRef / actualOutcome | 区分命令请求、授权与实际副作用 |
| existingChecks / manualAcceptance / notVerified | 区分证据来源和缺口 |
| recoveryActions / remainingRisks | 支持后续排障和回退 |

日志只保留必要内容，敏感信息不进入文档或客户端公开投影。清理退休 payload 前保留索引、源码身份和内容摘要，保留用户数据与活跃工作。

## 5. 发布停止条件与回退

出现重复不可逆副作用、越权执行、未验收代码回写、旧 epoch 错误获准集成、无法解释的任务消失或备份不一致，应停止新 Factory 准入并进入处置。

回退顺序：

1. 关闭新准入和外部发布，保留读取/观察/取消/对账。
2. 清点活动 Run、未知操作和待集成候选，等待或受控停止；不能仅清锁恢复表面正常。
3. 保持 Factory-owned 记录由兼容版本收尾，不交给不了解新状态机的旧代码。
4. 按实际 schema 兼容决定降版本或保留修复版本；不通过删除新表消除错误。
5. 已发生的合并/发布依据明确授权补偿，不能靠还原数据库宣称外部效果已撤销。

恢复稳定后，记录原因、影响和重新开放条件。与本工作无关的正常会话和其他并行任务保持原有生命周期。

## 6. 最终完成标准

只有在声明的平台范围内满足以下条件，才可以将 Factory 标为可用：

- 团队/任务长期存在，退出和实际重启后的事实仍完整。
- 用户可在进行中真实指挥，命令的请求与生效清楚区分。
- 多 Harness 在同一工作图中按相同契约交付可验证成果。
- 换人、重试、返工和恢复保留历史，重复事件不会重复造成副作用。
- 真实证据支持任务验收，候选、集成、包与审批一致。
- 已有用户路径兼容，能力不足时诚实拒绝，回退不丢事实。

若只有部分平台或部分执行模式达到条件，按该范围交付并列明其余未完成；不能为完成阶段编号而修改验收标准。
