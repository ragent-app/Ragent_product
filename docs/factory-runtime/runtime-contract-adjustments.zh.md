# Factory Runtime：报告解释与任务合同保护调整方案

状态：已审方案，待实施，基线 `main` / `7b9de9e4`。本文不改变产品代码，也不代表方案已实施或验收。上位范围与原退出标准见 [总方案](00-master-plan.zh.md) 和 [剩余工作](remaining-work.zh.md)。保留现有共享后台 broker、任务级授权和预算机制。

## 为什么调整

真实窄审中，Run 已完成，Attempt 成功，系统生成了不可变 ResultPacket 和报告候选；owner 根据冻结合同对报告作出 **failed**，工作项仍在 review。结果包外层 `succeeded` 表示执行完成；同一正文内模型的结构化声明却是 `blocked`，其阻断理由没有进入结果包的结构化 blockers 字段。这些是不同层的事实：人工决定没有被自动绕过，但目前用户不容易直接看清模型声明及其来源。该次报告为何误解任务要求尚无证据证明，不能推断是提示词、解析或其他单一原因。

另有独立的源码风险：`buildTaskPrompt` 把任务目标、验收标准、依赖和输出约定拼接后统一截到 48000 字符，虽然会追加通用截断标记，但尾部必需内容可能被裁掉，且标记不说明丢失了哪些必需字段。该阈值是代码中的字符限制，并非协商得到的模型上下文窗口；Factory 命令入口另有限制请求体为 64 KiB。上次实际 prompt 为 13902 字符，没有触及该上限，不能把该风险当作此次失败原因。

## A. 明确展示报告与模型声明

1. 对新产生的 Factory 报告，保留 Run/Attempt 执行状态、原始不可变 ResultPacket、原文、摘要和 digest；原始最终消息必须仍能关联已 finalized 的对应 Run、request、session、事件与内容摘要。结果展示复用现有控制块工具，将用户可见正文与协议块分开；原文仍可追溯，不因展示而改写。
2. 将唯一、完整、合法且有界的结果协议块作为**模型声明**展示，明确声明状态和阻断/风险等内容，并提供 `valid`、`absent`、`invalid`、`ambiguous` 等解析状态。没有块、多个块、截断、格式错误或来源不完整时如实标明，不从自然语言关键词猜状态。现有委派解析器会取第一个块并截断，直接复用前须补足这些边界。
3. 模型声明是意见：其 `blocked` 不自动关闭候选，`tests` 或自报验收不能成为可信检查或 owner 的通过决定。人工验收仍须针对固定合同、候选和证据明确作出，保留当前独立审查等门槛。
4. 对**新创建入口**的报告候选，建议要求有可读报告内容：去除控制块后的可见正文非空，或唯一合法结构化声明中的 summary 非空。展示时分别标示可见正文和模型声明 summary，必要时以后者作为明确标注的显示备用；合法的纯结构化报告不应被拒绝。只有控制元数据而无任何可读报告内容时才视为空；先检查消费者兼容性和同 Run 重放，缺内容明确报告原因。已创建的历史 packet、候选、digest 和既有决定不追溯改判；旧记录可只读展示为历史或未解析，不能为补投影改写内容或重算身份。

可能影响：仅返回无可读 summary 的控制元数据的客户端或任务以前可能形成候选，新入口会被拒绝，须先确认受影响调用者及恢复提示；历史记录依旧可读。不能把缺块统一视为失败，也不能从模型意见推导测试结论。

## B. 长任务保持完整并继续执行

完整冻结合同及其版本、任务身份、授权范围和验收标准始终是权威；上下文处理不修改用户目标，也不授予新权限。任务明确要求的知识引用与依赖证据是必需材料，不能默认作为可选内容裁掉。仅对已有明确可裁边界的补充材料自动选择，并记录省略范围。

**实际容量容得下时一次完整直传。** 移除对整段任务的人为 48000 字符截断，同时受控处理 64 KiB 命令入口及后续实际传输与存储边界，不作无界扩容。优先核实合同、交接和其他上下文是否重复注入，仅在保留语义、授权和必需证据的前提下消除重复或明确非必要内容；不能预设当前必有重复缺陷。根据已知 runtime 的上下文能力和任务预算，为系统内容与输出保留余量；未知能力或近似 token 估算须如实标明，不能宣称容量无限或将字符数当准确 token 数。默认不另做预摘要或分段调用，但不限制任务正常获准的工具执行。完整传递修复合同缺失，也可能比原先截断使用更多 token，不能承诺成本下降。

**确实超出实际窗口时按需选择。** 同任务受限读取或有界分段消化是后续候选能力，并非本轮必须建设或默认自动启用。若未来使用，须先说明额外调用的必要性、预期收益和不确定性，核对现有授权、次数与预算上限；不把同一任务视作额外调用授权，也不自动新建语义不同的工作项或重试。记录处理进度、预算消耗、已覆盖与未覆盖材料及原文来源；覆盖只表示原文已实际交付，不证明摘要无遗漏或模型理解正确。摘要可能有损，不替代权威合同。明确的单 Run、调用次数、工具及预处理限制仍须遵守。

成本按任务全程所有调用的输入和输出计量；重复前缀以及摘要/汇总属于这些输入或输出的成本来源，不在总量上再次相加。缓存输入是输入的一部分，不重复相加，也不意味着免费。费用和延迟分别说明，受 provider 与执行方式影响；去重、按需读取或多轮处理均不保证降低总 token 或费用。预估与实际用量应区分，不为此新增成本平台或验证实验。

受限读取须绑定当前 Run、任务、合同版本、材料身份和当前授权，并在使用前核对；当前尚未证实已有可供 worker 按任务分页读取完整合同的入口，若未来采用该方式，需先作必要的窄补充，不能只提供不可读取的 ID。对不允许工具的任务，不能暗中赋予读取权限；可采用该 runtime 和任务授权允许的分段输入方式。若真实容量、预算、显式权限或可用通道确实不能交付必需材料，保留原任务和进度，说明未覆盖范围及可恢复选择，而非以要求用户缩短内容作为常规路径。例如保留当前任务，扩大预算后继续处理或切换到可承载的执行配置；仅在既有授权范围内自动进行，否则由用户选择，默认不重跑全部内容。

现有上下文组装器的预算与来源记录可供复用，但其默认影子模式、近似估算和现有文本裁剪本身不能证明完整交付；native compaction 处理既有 thread 历史，也不等于首轮长输入已具备分段能力。不同 runtime 的实际通道与上限须分别核实，不承诺所有 provider 均支持同一种方式。

研究参考：[The Complexity Trap](https://arxiv.org/abs/2508.21433) 在 SWE-agent / SWE-bench Verified 的比较中发现，简单遮蔽旧观察与模型摘要具有竞争力，相对保留原始历史可降低成本。这不证明摘要必然增费或节费，也不能直接用于删除本系统的必需证据。

## 实施顺序、核查与停止条件

1. **报告解释**：检查 [协作执行器](../../chat/collaboration-orchestrator.mjs) 的 `finalFactoryReport` / `completeRun`、[结果包](../../chat/result-packets.mjs) 的 `deriveExecutionPacketFromRun` / `normalizeResultPacket`、[控制块](../../chat/assistant-control-blocks.mjs) 的 `stripAssistantControlBlocks`、[委派解析](../../chat/delegation-result.mjs) 的 `extractDelegationResult`，以及 [报告证据](../../chat/factory-report-evidence.mjs) 与 [人工验收](../../chat/factory-acceptance.mjs) 的调用边界。选定版本化的添加式只读投影和新候选判据后实施；检查历史摘要、唯一 Run 对应 packet、客户端显示及显式 owner 决定的兼容性。
2. **长任务交付**：先调整 [协作执行器](../../chat/collaboration-orchestrator.mjs) 的 `buildTaskPrompt`、[Factory 执行适配器](../../chat/factory-execution-adapter.mjs) 的 `executionObjective` 和 [命令入口](../../chat/router-factory-routes.mjs) 的受控传输限额，核对 [任务交接](../../chat/factory-task-handoff.mjs) 中合同与材料的实际可达性及重复注入，使可容纳的任务一次完整直传。真实超窗口的受限读取或同任务有界分段留作按需候选，不作为本轮必须建设或默认启用；不能把影子组装器或历史 compaction 说成已完成此链路。保留身份、幂等、预算和未知状态事实，不引入通用上下文平台。

两步均先实施，再静态审查修改和直接依赖；只运行确有可信预期且与改动有关的既有检查。既有真实结果包、合同、人工决定和 Run 是历史兼容证据，不证明未来新路径已通过；如缺对应现成覆盖，应明确记为未验证。任何新增测试或测试基础设施须按 AGENTS 先获明确许可，不制造样例、mock 或预期结果。真实运行须单独记录授权、预算、内容身份与实际结果。

停止条件：不能可靠绑定最终正文来源、无法保留旧 packet/digest、不能将模型自报与可信证据分开，或无法证明必需材料已按授权完整交付或按段覆盖时，不得宣称对应结果完整；保留任务及可追溯进度，报告具体缺口和可恢复选择，不以缺信息推断成功。

## 本次明确不做

不改本例的任务措辞或角色来针对结果；不加 `BLOCKED` 关键词补丁、特例状态映射、自动重试或第二模型裁判；不重构共享 broker 或预算；不因模型自报 blocked 自动禁止候选，不自动放行或改写历史失败决定。这两项调整改善合同完整性与信息可见性，**不能保证同一案例再次通过**。
