# 阶段 F 语音与产品体验

[上一阶段 E](phase-e-devices-connectors.zh.md) · [返回总览](README.md)

目标：让用户通过现有语音入口查询、创建和修改责任，并继续当前任务上下文。依赖 A–C 的业务 API 稳定；多设备语音续接依赖 E，涉及执行者交接时沿用 D 的规则。

## 复用基础

复用现有 Android/语音入口、voice connector 和 Web/Android 任务界面。原审计发现旧 local-voice API 有返回 410 的退役契约；实施前核对现状，不因历史组件仍存在而恢复退役服务。

## 工作包和顺序

| 工作包 | 实施内容 | 交付 |
| --- | --- | --- |
| F1 语音命令 | ASR 文本进入业务 Intent Routing，查询/创建/修改现有责任 | 与文本入口一致的命令适配 |
| F2 上下文对话 | 引用当前责任与真实运行状态，支持连续讨论、打断和回复 | 可追溯的上下文续接 |
| F3 多设备体验 | 手机查询电脑任务、跨设备延续讨论 | 复用目标设备授权和回执的交互 |
| F4 审批与移动端 | 聚焦运行中任务、待决定事项、重要成果 | 责任、Activity 和审批的清晰状态展示 |

## 业务与权限边界

语音识别、推理和 TTS 采用独立适配器，避免将特定模型写死在 Runtime。语音指令调用相同的责任命令和 Factory API，沿用 actor、版本约束、幂等键及政策检查。

用户询问“昨天任务如何”时，从责任、Work Item、Run 和证据查询真实状态；历史聊天摘要不充当执行事实。修改指令需要准确关联目标和当前版本，歧义未消除前不能写入错误对象。

语音可以收集意图和解释审批内容，但识别出的“同意”不能自行替代现有敏感授权。需要批准的动作转入现有审批界面，并固定对象、操作和内容版本。识别失败、网络中断、打断或重复提交不能产生未获确认的高风险动作。

## 产品交互

保留 Session 作为具体对话与执行入口；Responsibilities 展示持续目标、订阅、预算和授权；Activity 展示观察、决定、结果和待处理事项。Organization View 继续呈现复杂团队任务，不在 Android 首页塞入完整组织管理图。

移动端优先回答三个问题：什么正在执行、什么需要我决定、有什么重要成果。区分已受理、已派发、等待审批、执行已停止和结果未知；持续责任完成一轮工作不显示成整个责任已完成。

## 退出条件与交付

交付语音 Intent 到业务命令的映射、上下文续接规则、适配器边界、移动端和审批界面变更、真实设备验证与回滚记录。

用户能通过语音创建、查询、修改责任，能引用正在执行的任务；需要时进入审批界面；语音失败或重复输入不会越过授权；多设备状态以实际结果为准。支持范围逐设备、逐适配器记录，未验证能力不标为已上线。

遵守[共用架构](architecture-and-boundaries.zh.md)和[验证发布规则](verification-and-rollout.zh.md)。本阶段不重写自治控制面，不恢复旧本地语音服务，也不赋予语音入口额外权限。

## 当前工作区进度

组织任务入口已有责任读取、活动和命令审阅；Android 可将现有识别草稿送至选中责任提案，确认后调用同一业务命令并保存 Session 责任引用。草稿不会自动发送。本机 TTS 可按用户请求朗读真实活动，停止或离开视图会停止朗读；跨设备身份、音频焦点与连续交互尚未通过设备验收。详见[实施状态](implementation-status.zh.md)。
