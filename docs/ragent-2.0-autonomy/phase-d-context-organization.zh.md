# 阶段 D 长期上下文与组织调整

[上一阶段 C](phase-c-github-ci-autonomy.zh.md) · [返回总览](README.md) · [下一阶段 E](phase-e-devices-connectors.zh.md)

目标：让责任在多轮执行、上下文压缩和执行者替换后，仍保留一致的目标、依赖、权限及完成证据。前置条件是 A–C 的责任与工作关联稳定。

## 复用基础

复用 Project Memory 的 SQLite 提交、来源范围、任务租约和恢复；复用 Organization 节点、Grant、绑定代次、重新规划与消息机制；复用 Factory 版本化合同及现有交接模块。所有能力仍需以当前代码核对，不能根据原审计推断已经通过真实业务验收。

## 工作包

| 工作包 | 实施内容 | 交付 |

| D1 上下文组装 | 汇集责任定义、当前合同、源事件、ResultPacket 和已验证 Project Memory | 有来源及版本的执行上下文 |

## 上下文和记忆约束

责任进度从权威工作记录投影，不在 Responsibility Memory 再保存一个独立进度副本。检索先按项目、责任和权限筛选，再按证据质量和上下文预算组装。摘要不能提升为永久指令，外部内容不能修改授权。

先完成上述有来源的上下文，再扩展 User Memory。用户记忆必须有查看、更正、删除与来源界面，不先建设通用向量库来替代事实治理。

## 组织与目标变化

目标修改先产生影响清单；范围或验收变化形成新合同版本。运行中任务不能静默改约，旧候选、审查和审批是否可复用需显式决定。已完成工作保留历史，通过关联的新任务处理后续修复。

执行者失效或更换 Harness 时，查询旧 Run 与外部效果，再决定等待、停止、隔离或重新委派。旧执行代次不能提交新的有效验收或集成。子 Agent 的有效权限受上级、组织、责任及任务授权共同约束，换绑不扩权。

成本分工先满足权限、能力、工作区和并发限制，再比较成本。每日预算明确时区、跨日归属及责任范围，组织总预算继续生效。缺少真实用量或 provider 强制限额能力时，保留未知/估计状态及处置规则。

## 退出条件与交付

交付上下文契约、来源和有效性规则、目标修订影响协议、结构化交接与换绑流程、预算窗口设计及实际验证记录。

包含依赖的长期工作在执行者替换、重启和上下文压缩后，目标与授权版本保持一致；失效候选和审批不会继续被使用；记忆可追溯、可纠正；未知执行结果不会被盲目重放。未取得真实证据的部分如实标为未验证。

遵守[共用架构](architecture-and-boundaries.zh.md)和[验证回滚规则](verification-and-rollout.zh.md)。本阶段不引入第二套 Goal-DAG、组织角色、费用账本或记忆中的任务状态机。

## 当前工作区进度

责任上下文读取责任及活动、同项目记忆版本与来源、经授权工作关联及 Factory 合同和候选。读取跨多个存储，不构成原子快照；责任或记忆版本变化时返回冲突。来源分类不完整，冲突状态只作事实展示；记忆更正/撤销已有预览和受控写入源码，写入默认关闭，历史证据保留而非物理删除。目标修订、失效和预算窗口已有部分源码，执行者替换及真实重启换绑仍未验收；详见[实施状态](implementation-status.zh.md)。
