# 阶段 E 跨设备和外部动作

[上一阶段 D](phase-d-context-organization.zh.md) · [返回总览](README.md) · [下一阶段 F](phase-f-voice-experience.zh.md)

目标：在明确设备能力和授权的条件下扩展执行地点，并统一外部动作的准入、回执和恢复语义。依赖 A–C 的身份、授权和恢复契约；需要跨执行者交接的功能依赖 D。

## 复用基础

扩展现有 target-runtime 精确 method/path 授权与连接基础。Agent Capability 描述 Agent 能力，不能直接当作设备注册表。Connector SDK 的入站 Session/消息投递，与 connector-action-dispatcher 的 email/calendar 完成动作具有不同职责，均不能直接等同自治动作授权。

## 工作包

| 工作包 | 实施内容 | 交付 |
| --- | --- | --- |
| E1 设备事实 | 注册、在线状态、能力发现、容量和实际隔离能力 | 可用于调度的设备能力快照 |
| E2 远程派发 | 主体与资源约束、工作区位置、受理回执和结果查询 | 现有执行链的远程适配契约 |
| E3 数据传输 | 跨设备文件与结果传输的授权、身份及回执 | 独立于执行授权的传输边界 |
| E4 外部动作 | 逐个统一 GitHub/Gmail/Calendar/Drive 动作 | 政策、幂等键、回执和未知结果协议 |
| E5 分平台验收 | 设备离线恢复、权限限制和 provider 差异 | 基于实际证据的平台/动作能力矩阵 |

## 设备调度和恢复

设备事实分别表达软件已安装、当前在线、主体被授权、实际可强制隔离。调度先检查这些硬约束，再考虑资源和偏好；设备在线不代表任意操作都被授权。

首版保持一个权威实例统一派发，再增加远程执行适配。设备离线时区分未派发、已受理但未回执、已执行但结果未同步。后两者先查询真实状态；不能根据连接超时推断执行失败或跨设备重跑。

操作系统或 Harness 没有可证实的只读/隔离能力时，明确降级或拒绝对应无人值守操作。平台适配器遵守同一能力契约，不宣称 Windows、macOS、Linux 已经具有等价保证。

## Connector Action 契约

| 字段 | 用途 |
| --- | --- |
| capability、scope | 描述操作、账户和资源边界 |
| riskLevel、confirmationPolicy | 区分只读、可逆写入、不可逆写入和外部传播 |
| idempotencyKey、timeout | 识别逻辑动作并限制等待 |
| receipt、结果查询 | 记录真实外部受理及执行结果 |
| compensation | 描述可用的补偿方式和所需授权 |

OAuth scope、入站传输成功和自治动作许可分别核实。创建邮件草稿与发送邮件、读取 PR 与合并 PR 分别授权；不能只给现有函数套统一字段就宣称安全统一。

外部效果无法与本地数据库天然原子提交。有可查询/幂等能力时据此恢复，无法核实的写入进入 unknown_outcome；补偿是另一次受控动作，不默认等于回滚成功。跨设备传输和外部传播需要独立授权。

## 退出条件与交付

交付设备能力与调度约束、远程回执及恢复协议、传输政策、四类连接器的逐动作能力清单、分平台真实证据、风险和回滚说明。

在明确授权和设备限制下完成真实跨设备任务；正确处理离线和回执延迟；未知效果不会重复执行；权限与传输边界可追溯。某平台或动作未验证时，不扩大“跨平台可用”声明。

遵守[共用验证和灰度规则](verification-and-rollout.zh.md)。多主一致性调度、默认生产发布和无限连接器扩张不属于本阶段默认范围。

## 当前工作区进度

邮件和日历完成动作已区分未知结果并阻止无证据重放；Google Calendar 可用确定性事件身份及内容摘要查询正向回执。邮件人工核查只记录人工观察。设备快照区分事实和未知，本机服务存在可证明本机安装及在线，但目录不证明远端隔离或授权。单权威远端派发、受端受控执行、候选回传和单文件独立授权已有源码接线，默认关闭且尚未通过真实设备和提供方验收。详见[实施状态](implementation-status.zh.md)。
