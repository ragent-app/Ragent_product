# macOS 审批与执行组件设计

## 状态和目标

本文是实现约束，不代表 macOS 审批能力已经可用。当前的命令识别和安装包
检查只提供诊断，所有 macOS 语义审批仍须拒绝。只有完成本设计中的执行链、
原生验证和发行验收后，才能将对应操作从拒绝改为可审批。

目标是在 macOS 13 及以上的 Apple Silicon 系统上，将所有者批准绑定到一个
明确的操作，并由独立执行组件复核和执行。先支持有限的操作适配器；不提供
通用 root shell，不允许客户端传入任意可执行文件、环境变量或脚本。用户态
操作和需要管理员权限的操作必须有独立权限边界，不能用用户态进程冒充 root
助手的安全保证。

## 身份和信任边界

- UI 收到的命令、工作目录、包名和服务标签均不可信。服务端从已绑定的
  Run 和其不可变执行范围构建操作；所有者批准只选择服务端生成的操作。
- 本机其他同 UID 进程不能仅凭路径、进程名、PID、命令行、网络端口、
  环境变量或客户端自己提供的签名字符串获得助手权限。系统级助手须在
  受保护的本机通信通道上验证连接对端的操作系统身份和代码签名身份，并
  按构建时固定的签名要求验证，而不是信任请求中的身份字段。
- 助手的程序、配置、验证密钥及一次性授权账本必须受系统权限保护；安装、
  升级和卸载均需验证实际文件、所有者及签名。开发期 ad-hoc 构建只能用于
  隔离测试，不能作为正式身份策略的依据。证书轮换必须有明确的过渡策略。
- 所有者批准必须经过现有交互认证，绑定 session、run、turn、请求、操作
  集合摘要和短期有效期。签名授权不可变、仅能使用一次；助手自行验证
  签名、用途、范围、有效期与重放状态，且不得信任客户端声称已经验证。
- 保护密钥和账本应由助手控制；请求进程、工作区、提供商与普通用户可写
  文件不能替换它们。助手崩溃或系统重启后，已消费的授权仍不可重放；状态
  无法持久化时拒绝执行。

## 操作和目标

首个可交付适配器应选定单一操作并完成全部验收，后续逐项扩展。每种操作
必须分别定义允许的参数、完整副作用、目标身份、审批展示、执行方法和
复核方法；未知参数、复合命令、重定向、环境赋值、变量展开及未建模副作用
一律拒绝。语义预览识别出的命令不自动成为适配器。

文件目标必须使用服务端可信的工作区和当前目录解析，检查大小写、Unicode、
符号链接、硬链接、挂载点和系统受保护目录。授权中记录规范目标及稳定身份；
执行前由助手从可信目录句柄重新解析并核对，不可仅依靠路径字符串或一次
`realpath` 检查。创建、替换、递归删除和跨卷移动分别有不同的竞态与权限
规则，不能共用一个粗粒度的“项目内路径”判断。文件系统状态不能安全复核
时拒绝；系统保护、隐私权限或只读卷导致失败时不得绕过。

`launchctl` 操作必须区分 system、user 和 GUI 域，绑定实际 UID、服务标签、
域和操作；不得接受相对或动态解析出的服务目标。实际作业及其配置可能在
审批与执行间变化，适配器须定义可复核的身份；无法稳定证明时拒绝。系统
域操作不应通过用户域助手执行。是否允许修改或加载服务配置必须另行设计，
不能由重启服务的授权推导出来。

安装包操作不能仅凭扩展名、路径、文件摘要或 `pkgutil` 输出取得执行权。
需要可靠识别包对象、签名与信任状态、安装目标、脚本及其实际副作用，并
在执行边界防止目标替换。安装脚本可能具备广泛系统权限；在无法完整约束和
向所有者准确展示其效果之前，该类操作保持拒绝。Homebrew 则有独立的用户态
信任、依赖解析和供应链问题，不能借用系统安装器的授权。

## 执行和故障处理

助手接收结构化、版本化操作，而不是 shell 字符串；为每个适配器使用固定
的系统程序或原生 API、固定参数构造和最小环境。先验证调用者、授权和当前
目标，再以原子方式消费授权，最后执行。执行前拒绝与执行后失败必须区分；
授权已消费但结果未知时不得自动重试。运行时间、输出大小和并发受限，退出、
超时、取消和助手重启后的结果均有明确状态，不以客户端断开推断操作未发生。

审计记录应包含操作摘要、授权 ID、请求绑定、目标身份、执行身份、时间、
结果和有限的脱敏诊断；不得记录凭据、完整环境或无界命令输出。普通用户
不能修改系统助手的审计与重放账本。日志或账本不可用时的行为须明确并测试。

## 生命周期与验收

安装过程应使用受支持的系统服务注册机制和明确的本机管理员授权；不得
使用未经验证的 `sudo` 脚本或静默提权。需要完成助手身份验证、注册、启动、
健康检查、失败恢复、版本兼容、升级回滚和卸载。卸载时仅移除产品拥有的
服务和文件，保留用户数据；遇到不匹配的既有服务或文件时停止并提示。

在隔离 Mac 上，对每个开放适配器至少验证：正常批准与拒绝、篡改操作和
目标、跨会话或跨 Run 复用、过期与重放、并发双重消费、助手崩溃与重启、
目标替换、符号链接及硬链接、大小写和挂载点、非授权进程伪装、错误签名、
不匹配版本、权限不足、超时和卸载重装。还要通过实际 UI 到助手的完整链路
核验审计及结果，而不仅是模块测试。正式验收另需 Developer ID 签名、公证、
装订和干净机器上的 Gatekeeper 测试。

在这些条件完成以前，`darwin` 语义解析、策略、授权签发和执行器必须继续
默认拒绝。具体适配器可分阶段实现，但每次开放都必须同时交付身份校验、
执行前复核、一次性授权、审计和相应的负向验收。
