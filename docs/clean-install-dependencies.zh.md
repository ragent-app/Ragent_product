# Ragent 全新系统安装与依赖验收

目标是在支持的 Windows、macOS、Linux 系统上，从全新用户账户安装后即可启动和连接；用户无需预装 Node、npm、Go、Python、Git 或编译工具。构建机所需的工具不应成为用户机器的运行前提。支持范围必须按操作系统版本、CPU 架构和 Linux 发行版明确列出，不能把所有空白系统一概视为兼容。

核心服务、桌面管理器、Node 运行时、生产依赖和 P2P 程序应随对应平台安装包提供，并在包构建阶段验证版本、架构和完整性。默认使用受控的应用私有运行时，不覆盖用户系统的 PATH 或已有工具。打包的默认执行器同样应检查其原生二进制、运行库、许可证及身份登录要求；用户自己的账户登录不能由安装器替代。

非核心执行器和可选功能按需检测；缺失时展示组件、来源、大小、所需权限和失败原因，提供安装或修复操作。下载需使用可信来源、固定版本及完整性校验，先安装到临时目录，再验证并原子启用；失败或中断应保留原可用版本并支持重试。用户环境已有组件时应识别版本与路径，不覆盖已有软件或凭据。系统级组件必须通过平台支持的安装方式和权限机制处理；不支持的系统版本及 CPU 架构要明确提示，不能误报安装成功。

离线条件下，完整安装包应能完成其已包含功能的安装和本地启动；账号登录、远程连接、更新和未随包提供的可选组件需要网络时，应明确说明并允许联网后重试。避免把所有失败都归为“依赖缺失”：区分权限不足、网络不可用、磁盘空间不足、版本不兼容、校验失败和第三方登录未完成。

验收必须在快照恢复后的干净虚拟机或真实机器上进行，而不是仅清空 PATH：Windows、macOS、每个声明支持的 Linux 发行版及 CPU 架构分别覆盖首次安装、首次启动、默认执行器、手机配对和附件上传；记录精确系统版本、镜像、安装包哈希与结果。还需覆盖标准用户、无网络或网络中断、缺少空间、损坏依赖、重新安装和升级；验证重复运行不会产生第二个实例或删除工作区、配置和凭据。对无法自动修复的系统前提，应给出可执行的修复指引。该文档是验收要求，不表示这些场景已经通过。
