# Central Accounts speech recognition

## Decision and scope

Run cloud speech recognition inside the existing central Ragent Accounts service. The Android app sends audio directly to Accounts over the account service's HTTPS endpoint; Accounts authenticates the Ragent account, applies its quota, calls the configured speech provider with a server-only key, records usage, and returns text to Android. This adds no client-side provider secret, local forwarding daemon, separate ASR database, or new server product.

The existing Android and paired-computer routes remain local. Automatic voice routing continues to prefer the session computer's enabled Whisper service and then the phone's system recognizer. It never chooses cloud recognition by itself. Cloud recognition is a separate per-chat choice that requires the user to select it, accept the current upload disclosure, and receive an Accounts confirmation before microphone capture starts. Every successful route writes to the draft; it never sends the chat message.

## Request path

1. Android records mono 16 kHz PCM16 WAV from the phone microphone, for 0.5–20 seconds and no more than 1 MiB.
2. Android sends the raw WAV bytes to `POST /v1/owner-auth/account/asr/transcriptions` at the configured central Accounts base URL. It includes the existing RAC bearer credential and a per-recording `Idempotency-Key`.
3. Accounts validates the credential against the account directory, device status, and current Free/Plus/Pro entitlement. It reserves monthly account minutes transactionally in the central PostgreSQL database before contacting the provider.
4. Accounts forwards audio to ElevenLabs Scribe v2 without a language code, so language detection is automatic and independent of Android's UI language. The ElevenLabs key stays in `/etc/agentoc/accounts.env` on the Accounts host.
5. Accounts settles the usage ledger and returns `{ contractVersion, requestId, text, languageCode, durationMs }`. Android validates the response and puts only `text` into the current draft.

`GET /v1/owner-auth/account/asr/usage` returns the signed-in account's current period, plan, cap, used/reserved/remaining milliseconds, and request count. It does not return provider cost to a customer. The database keeps an estimated provider cost for internal reconciliation.

## Quota and accounting

Quota is shared across all devices on one Ragent account, not per phone. Initial monthly caps are Free 15 minutes, Plus 120 minutes, and Pro 600 minutes. Operators can change them with `AGENTOC_ACCOUNTS_ASR_FREE_MINUTES`, `...PLUS_MINUTES`, and `...PRO_MINUTES`. These are usage caps, not customer ASR charges. ElevenLabs's [official pricing](https://elevenlabs.io/pricing/api?price.section=speech_to_text) listed Scribe at $0.22 per audio hour when checked on 2026-11-10; the integration does not request the separately priced entity-detection, keyterm-prompting, or transcript-editing options. At the base rate, the approximate maximum provider cost at those caps is $0.055, $0.44, and $2.20 per account per month, before tax, plan changes, add-ons, or invoice-specific terms. Recheck the actual account pricing before launch.

The database migrations add `account_asr_usage` for account-period totals, `account_asr_requests` for idempotency and request-state metadata, and `account_asr_consent_events` for affirmative consent/revocation evidence. Request metadata includes duration, byte count, a content digest, device, provider/model and price/policy versions, latency, language, state, and estimated provider cost. Audio and transcript text are not written to PostgreSQL or files. Ragent keeps a bounded in-memory transcript result for five minutes only to answer a same-process idempotent replay. Successful/failed request metadata is pruned after 90 days; monthly totals stay until account deletion, and the account-deletion cleanup removes their rows.

Consent is enforced centrally before request reservation, provider forwarding, and cached-result replay. A disclosure-version change requires fresh acceptance. Consent events contain only account and device identifiers, the disclosure version, the accepted/revoked action, and timestamp; they are intentionally kept outside the account-deletion cleanup and purged after five years. The account-deletion receipt states that this minimal evidence remains. The privacy policy and prominent in-app notice must disclose that retention before cloud ASR is enabled.

Reservations are serialized by locking the account-period aggregate before locking a request. A confirmed success moves reserved minutes to used minutes; a definite pre-processing failure releases the reservation. A timeout or other uncertain provider result is never submitted again under the same key, and its minutes remain reserved until evidence-based operational reconciliation. A confirmed provider rejection releases the reservation without adding provider cost. If the provider confirms processing but the transcript was lost, reconciliation releases customer minutes and adds the versioned internal provider-cost estimate to the cost aggregate. Ambiguous cases remain unknown; never infer a result from an audio hash or timestamp alone.

## Privacy and provider boundary

Selecting the cloud route sends microphone audio to Ragent Accounts and ElevenLabs. Ragent does not store the recording or transcript in its database; a transcript can remain in server memory for up to five minutes for idempotent retries. The vendor's own retention and processing terms still apply: ElevenLabs documents request logging as enabled by default, and its zero-retention request mode is limited to eligible Enterprise customers. Do not enable zero-retention mode unless the provider account is entitled to it. Before public enablement, make the provider transfer, brief server-memory cache, account/device usage records, five-year consent evidence, and applicable vendor retention visible in the Android flow, privacy policy, and Google Play Data Safety declarations. Users who do not accept that transfer can keep using local phone/computer recognition.

The endpoint rejects non-WAV or unsupported WAV input, limits audio size and duration, rate-limits requests, limits each account to two concurrent operations, reserves account minutes before provider work, uses a 30-second provider timeout, and gives Android a 60-second overall request budget so it can receive the provider result. It rejects provider redirects, bounds provider response size, and never writes audio or transcript into service logs. The API is disabled unless both `AGENTOC_ACCOUNTS_ASR_ENABLED=1` and `ELEVENLABS_API_KEY` are present. Keep the key only in the protected Accounts host environment file; never put it in the Android or Windows package, source control, command line, or logs.

## User-visible behavior

- **Automatic**: local routing only; session computer Whisper first, then phone-local recognition. No cloud fallback.
- **This phone**: phone-local recognition only; no network fallback.
- **Paired computer**: Whisper on the selected computer only.
- **Accounts cloud**: explicitly uploads the current recording to central Accounts. The route shows availability and remaining monthly minutes. Quota exhaustion, account authentication errors, or service downtime do not switch routes silently.
- **Uncertain result**: do not automatically replay the recording. Tell the user the result is unknown and minutes may remain reserved; show current usage so the user can decide whether to make another recording.

The client currently presents cloud availability and remaining minutes in the voice-device picker. Cloud selection is stored using the existing voice-choice preference. The result continues through the existing composer draft callback.

## Deployment and rollout

1. Build the independent ARM64 Accounts release from the committed source. This is the central Accounts artifact, not an Ubuntu Ragent client build. Keep build output, temporary files, and caches on G:.
2. Keep the current Accounts release available. Copy the new immutable release under `/opt/agentoc-accounts/releases` and verify the source revision and archive checksum.
3. Apply additive migrations `038_account_asr_usage`, `039_account_asr_consent`, `040_account_asr_consent_disclosure_v2`, and `041_account_asr_reconciliation` with the protected Accounts environment file. Do not run their down migrations as part of rollback.
4. Atomically switch `/opt/agentoc-accounts/current`, restart `agentoc-accounts`, and check `/healthz`, `/readyz`, route prefix handling, and invalid-credential rejection. Keep the feature flag off while the provider key is absent.
5. After confirming the published privacy notice and Data Safety declaration match the actual provider account terms, and securely provisioning the provider key, enable the feature, verify usage for a signed-in account, and run a real, short multilingual utterance from Android. Confirm the audio reaches only Accounts and the provider, the text returns only to the draft, usage increments once, and no transcript appears in database rows or logs.
6. Monitor provider spend and request outcomes. Roll back application code by pointing `current` to the previous immutable release; leave the additive tables in place. Disable the flag immediately if usage, privacy, or provider behavior is wrong.

## Acceptance checks

- Valid RAC on a live Android account can read only that account's usage; invalid, expired, revoked, or missing credentials are rejected.
- Two devices on one account share the same monthly limit; parallel reservations cannot exceed the cap.
- Replaying one request with identical audio never calls the provider twice; a different audio body with the same key returns conflict.
- Invalid WAV, unsupported sample format, over 20-second audio, and over 1 MiB are rejected before the provider call.
- Known rejection releases quota; a timeout/ambiguous provider response is marked unknown, keeps quota reserved, and cannot be replayed under the same request ID. The reconciliation CLI is read-only by default, requires a named operator and evidence reference for writes, checks the aggregate/request invariant transactionally, and is idempotent.
- An explicit cloud transcription detects a non-phone UI language, returns a transcript, fills only the draft, and increments account usage once.
- Local routes and automatic routing still work with the Accounts feature disabled or the provider unavailable.
- Account deletion removes request and aggregate rows. No server or provider key is present in client packages or source.
