# Linux 托管删除的执行边界

## 现状

本文约束后续实现，不开启新的删除权限。真实 Codex 使用托管 MCP 请求删除
系统路径时，语义策略拒绝了请求。当前服务进程可能无法读取 root 私有目录，
现有文件解析器也没有可供特权执行器安全复核的完整目录身份。仅从 shell
包装中提取 `rm` 并交给旧特权执行器，会绕过语义路径的限制；该转换已撤回。
旧命令执行路径和语义审批路径的授权范围仍须统一审计。

`native/linux-target-preflight.c` 是独立的目标检查及单文件删除原型，尚未
装包、接入服务或签发授权。默认模式只检查，显式删除模式接收先前的身份
快照并再次核对，然后通过已打开的父目录句柄删除单个文件。身份数值以十进制
字符串传递，避免 JavaScript 整数精度损失；删除后目录同步失败时报告持久性
未知，调用方不得自动重试。它以 root 运行，从根目录句柄逐级检查路径，拒绝
非 root 所有或其他用户可写的目录和目标、命名或默认 ACL、符号链接、硬链接、
非普通文件和不同挂载；不能取得挂载身份或 ACL 信息时拒绝。它假定 root
及等价权限进程可信，不证明与此类进程并发修改的安全性。仅包含标准条目的
访问 ACL 在权限满足约束时可接受。输出的身份事实不是授权，尚未覆盖签名、
自保护策略、完整祖先身份绑定或产品级授权与执行时复核链。

`chat/linux-target-binding.mjs` 为后续授权绑定提供严格的数据格式：规范化的
绝对路径与所有原生身份字段共同计算摘要，整数使用规范十进制字符串并校验
范围，拒绝未知字段、控制字符和不完整 Unicode。已用真机原型输出和单元
测试验证格式；这个模块不会证明快照来自特权执行器，也不会签发授权或开放
执行。尚须把可信来源、该摘要、操作和一次性能力完整连接起来。

Linux 默认语义解析器已改用大整数读取设备号和 inode，避免超过 JavaScript
安全整数范围时错误匹配目标；文件大小无法安全表示时，解析结果保持不完整。
解析器目前的 `mountId` 实际是设备号，而原生组件使用内核挂载 ID，两者
不能直接比较；同设备绑定挂载的完整复核仍需后续实现。

`chat/linux-target-attestation.mjs` 增加独立的 Ed25519 快照签名协议，绑定
公钥身份、session、run、turn、请求、目标路径与身份摘要，签名最长有效
5 分钟。校验使用调用方提供的可信公钥，拒绝上下文、路径、身份和签名被
修改、未知字段、未来签发时间或过期。隔离单元测试以及真机原型产生的
快照签名验证已通过。模块不创建或保护密钥、不证明调用方提供的公钥可信，
也不提供一次性消费；当前既不接入生产通信，也不能用作删除授权。

`chat/linux-target-key-store.mjs` 提供独立的 Linux root 密钥存储原型：在
root 控制且不可由其他用户写入的目录链下创建 Ed25519 私钥和只读公钥，
校验所有者、权限、硬链接、符号链接、记录格式和密钥匹配；私钥及目录
创建会同步到磁盘。缺少私钥时默认拒绝，只有明确的初始化调用才创建；已有
记录损坏时拒绝，不自动生成替代私钥；私钥存在而公钥缺失时可从同一私钥
恢复公钥。隔离真机测试覆盖重启式重新加载、普通
用户只能读取公钥、权限或所有者异常、链接、损坏与缺失的拒绝。该实现
仍未连接执行器或发布流程；接入时目录必须由产品固定，不得由请求提供，
还需确保仅在可信的首次安装中初始化，并验收文件系统、密钥轮换、升级和
完整通信的信任边界。

`scripts/linux-target-inspection.mjs` 将上述原型组合为仅供 root 调用的
预检流程：检查辅助程序的 root 所有权、目录权限、链接、ELF 架构和可信
调用方提供的固定摘要，通过已打开的文件描述符执行检查，再以提供的私钥
签名快照。隔离真机测试覆盖成功签名、摘要不符、辅助程序可写或被链接、
目标为符号链接及目录不可信时的拒绝。它尚未连接服务或打包；后续必须由
安装机制固定辅助程序路径和摘要，不能让请求方提供这两项，也须验证调用方、
预检披露范围、密钥生命周期和完整授权链。
该模块另提供独立的原生删除调用原型：输入必须是完整的身份快照，辅助
程序再次核对后删除；明确的执行前拒绝、完成和无法确认的结果分别返回。
超时、进程中断、删除系统调用失败或持久化不明均作为未知结果，不能自动
重试。隔离真机验证了身份不符和文件变化时拒绝，以及匹配快照时的删除；
它尚不验证用户授权或消费 nonce，不能直接接到产品执行入口。

`chat/linux-delete-observation.mjs` 将已验证的原生快照附着到服务端生成的
单文件 Linux host 语义审批决定，并重算操作摘要以供后续所有者选择绑定。
它要求当前策略重算仍为 ASK、自保护检查完整且未命中，核对会话、任务、
轮次、请求、路径、文件和父目录身份，拒绝未知事实、系统路径 DENY、
链接及身份不一致。该函数依赖调用方从可信存储取得语义决定和 root 公钥，
自身不能证明这些输入的来源；尚不连接产品，也不会创建执行能力。
隔离真机测试中，普通用户解析 root 所有的测试文件，root 原生预检后两侧
身份及签名快照成功绑定。另以夹具验证了策略拒绝、身份和签名篡改；这些
测试未覆盖产品接口、所有者实际审批或执行后的提供商结果。

语义能力的选择数据现可保留完整原生快照签名，使所有者选择摘要覆盖目标
身份和请求上下文。该步骤仅检查数据结构和绑定，不代替对 root 公钥的签名
校验。能力数据结构现支持单文件删除并可由现有所有者证明流程签发；产品
执行器仍拒绝该适配器。已在隔离真机上验证选择摘要包含原生快照，并运行
现有语义能力定向测试。

`scripts/linux-delete-revalidation.mjs` 增加未接线的 root 复核原型：检查
已选择摘要和请求绑定，使用可信运行上下文重新解析目标、重算语义策略，
验证 root 快照签名，再执行新的原生预检并比较完整身份。内置产品保护目录，
并要求调用方提供额外的可信保护目录。隔离真机测试通过正常复核，以及
摘要、上下文、保护目录、辅助程序摘要或文件内容改变时的拒绝。此函数
不验证所有者能力、不消费授权、不执行删除；其运行上下文、保护目录、
选择摘要、密钥及辅助程序身份仍必须由可信的产品边界提供，不能来自请求。

`scripts/linux-delete-capability.mjs` 在隔离原型中组合服务签名验证与 root
复核：签名、上下文、快照、当前策略或目标不一致均拒绝。该模块不消费
nonce、不检查实际 Run 的活跃状态，也不执行删除；重复验证可能成功，
不能将其结果当作一次性授权。真机夹具验证了所有者证明回调、签名能力和
root 复核，并确认现有产品执行器仍明确拒绝此适配器。可信运行上下文、
保护目录来源和完整执行链尚未接入。夹具还验证：即使服务密钥重新签署包含
伪造 root 快照签名的能力，root 复核仍拒绝。

`scripts/linux-delete-ledger.mjs` 增加独立的一次性消费原型：在 root 控制、
模式为 0700 的目录中对 nonce 摘要使用独占创建，写入记录并同步文件和目录
链后才返回消费成功；已存在的记录即使不完整也视为已消费。初版仅接受
Linux ext 系列文件系统类型；这不能证明底层存储为物理本地或硬件可靠完成
刷盘，记录不可随意删除。真机隔离测试覆盖同进程、跨
进程竞争、新进程重读、残缺记录及不可信目录拒绝；没有模拟断电或磁盘故障。
账本尚未接入执行器，首次创建与生命周期、磁盘耗尽、备份恢复、记录保留及
其他文件系统的安全处理仍需实现和验收。

账本原型还支持在已消费记录之后独占写入开始和结果记录，均在同步成功后
才返回；残缺或不匹配的前置记录不允许推进。`scripts/linux-delete-execution.mjs`
将独立模块串联：校验签名和可信 Run 上下文、复核目标、消费 nonce、记录
开始、再次检查活跃状态、调用原生删除并记录结果。结果记录失败时返回未知。
真机隔离夹具验证了最后一次活跃检查失败时不删除、同一授权并发请求只有
一次删除成功、结果记录及产品执行器仍拒绝该适配器。夹具的 Run 查询、
活跃状态和所有者证明均为测试替身，不代表产品真实审批和执行链通过。
另在删除调用前人为更改测试账本权限，使删除后的结果记录失败；原型报告
未知，测试文件已删除，nonce 仍被视为已消费。此故障注入不等同于断电或
实际磁盘故障验收。

在 Ubuntu 24.04.4 x86-64 物理机上，原型以编译器警告视为错误构建，隔离
root 测试覆盖普通文件、路径穿越、目录、文件及目录符号链接、硬链接、
可写目标和父目录，以及命名访问 ACL 和默认 ACL 的拒绝。另验证快照篡改、
目标内容改变、目标替换、审批后增加硬链接或父目录变为可写时拒绝，匹配
快照的目标可被删除且其他测试文件不变。
该测试没有覆盖并发替换、真实挂载切换、其他文件系统或产品端到端链路。

## 目标与非目标

先实现一个可审计的单个普通文件删除适配器，再逐步扩展；首版不支持目录、
递归、多目标、通配符、变量、shell、硬链接、符号链接、跨挂载点或调用者
指定的可执行文件。删除产品自保护对象、凭据及策略禁止的目标仍须拒绝。
不能把识别出的路径、模型描述或者用户点击当作执行授权。

## 目标事实和授权

- 管理员执行器提供受限的目标预检，通道必须使用已有本机对端身份校验。
  预检只接受明确的单个绝对路径，返回有限的目标事实和错误码，不读取文件
  内容。执行器自行解析路径；服务和模型提交的文件身份只作为待核对数据。
- 从根目录句柄逐级无符号链接地打开父目录，核对设备、目录及叶子身份。
  设计必须处理文件系统、ACL、挂载、大小写及并发替换；不能仅凭 `realpath`
  或字符串前缀。若无法证明执行时目标不会被非授权进程替换，则拒绝。
- 可信预检结果与服务端解析得到的操作、session、run、turn、目标及短期
  有效期一起绑定到语义投影和所有者选择。目标位于受保护范围时，必须先
  按明确的产品安全策略判断是否存在可审批例外；默认拒绝，不能假定所有
  系统路径可批准。投影中的 DENY 不得转换成 ASK 或降级到旧链路。
- 特权端独立验证请求方、签名、版本、适配器、操作集合和用户选择；持久化
  消费一次性 nonce 后重新解析和核对目标，身份变化、授权过期或账本失败
  均拒绝。目标复核与删除之间的竞态也必须由实现和信任假设明确解决。

## 执行、结果与生命周期

`chat/linux-run-scope-grant.mjs` 是尚未接入产品的 Run 范围签名原型：它绑定
已发布的 Run、session、request/turn、publication ID 和执行范围摘要，并限制
有效期；它还绑定启动次数，验证时必须由可信启动状态提供预期次数。范围摘要不包括 `snapshotId` 和 `createdAt`，因此这两个字段不能用作
授权事实。验证必须使用特权端预先固定的服务公钥；从服务可写的清单或密钥文件
临时读取公钥不能建立信任。签名本身也不证明 Run 仍在运行、所有者已批准或
路径安全。后续仍需安全密钥登记和轮换、root 控制的上下文保存、真实生命周期
核验、独立路径和策略复核，以及对长任务的安全续期；这些完成前不得接通执行器。

`scripts/linux-service-key-pin.mjs` 是独立的 root 公钥固定原型：只允许显式
首次登记，要求调用方提供经过独立可信渠道核实的 SHA-256 公钥指纹，以独占
创建和同步的 root 文件保存，不自动替换或轮换。它不负责证明指纹来源，也不
读取服务可写文件来决定是否信任；安装和轮换流程仍待设计。Linux 真机隔离
测试覆盖 root/非 root、错误指纹、重复登记、不安全权限、篡改和符号链接。

`scripts/linux-run-unit-liveness.mjs` 提供尚未接入执行器的 systemd 实例检查：
使用可信启动状态中的 Run ID、启动次数和 InvocationID，核对活动状态、主进程
及 cgroup 路径。Ubuntu 24.04 真机使用隔离 transient unit 验证了匹配与错误
InvocationID 的拒绝；实际 slice 包含父级 `agentoc.slice`。该检查不能证明
Run 未取消或操作仍获授权，检查之后实例也可能退出；尚需可信启动状态持久化、
取消同步和执行时竞态处理，不能仅据此开启产品执行入口。
身份捕获只能由实际创建该 systemd 单元的 root 生命周期管理器执行；根据
同名单元反向认领一个现存实例不建立启动来源。捕获失败必须令该能力不可用，
不能以空 InvocationID 或普通 PID 代替。

`scripts/linux-run-context-store.mjs` 在独立原型中组合固定公钥、签名范围、
真实 systemd InvocationID 和 root 私有运行记录；记录不保存审批通道令牌，
撤销标记存在时拒绝读取。文件和目录执行同步；预建目录自身必须先可靠落盘，
存储设备断电行为尚未验证。Ubuntu 真机隔离测试覆盖登记、重登记、启动代次
不符、读取、重复撤销及撤销后拒绝。记录可随启用的启动握手登记；统一 Run
取消入口会尽力通知 root 撤销，结束流程和其他取消分支尚未完全接入。
范围凭据过期即不可读取。原型续期要求旧凭据仍有效、
新凭据由固定公钥签名且范围相同、原 systemd 实例仍存活，并使用独占锁和
原子替换；Linux 真机测试覆盖续期、旧凭据回退、错误密钥、锁遗留及撤销后
续期。崩溃遗留锁需明确恢复，实际调度与长任务续期链路尚未接入。

隔离的登记执行器与撤销现在使用同一个 root 持有的跨进程操作锁。撤销先
持久化标记，再等待锁；执行器持锁复核标记、授权和目标，原生子进程继承锁
描述符。这样成功确认撤销时，先前持锁操作已退出，后续操作会看到标记。
Linux 真机测试覆盖了控制进程崩溃后子进程仍持锁、撤销等待以及原生删除
链路。当前只接受 ext 系文件系统和受保护的系统 `flock`，锁文件在安装
运行期间不得清除；不证明断电持久性。普通取消通知若未送达 root 或在标记
落盘前崩溃，服务恢复队列会重试；重试完成前仍不能证明 root 已撤销，不能因此
开放生产特权入口。

第二版目标证明在签名中加入启动次数和 systemd InvocationID；特权侧的
`scripts/linux-registered-delete-executor.mjs` 要求该版本，并以 root 保存的
运行记录构造预期上下文。第一版仅保留原型兼容，不可用于该执行入口。
Ubuntu 真机上的隔离链路覆盖了真实 systemd 单元、固定公钥、root 记录、
第二版证明、模拟所有者证明、一次性账本和原生单文件删除，并验证错误启动
次数及撤销后拒绝。该测试并非产品 UI、真实所有者认证或安装包验收；生产
取消同步和结果回传尚未完成，执行入口保持关闭。

生命周期服务现有可选登记接收端：只有 root 配置了记录目录和公钥目录，
且启动请求携带范围凭据时，才在本次新建单元后尝试登记；复用现存单元不会
重新认领身份。登记失败不会阻断或重复启动普通任务，特权能力仍不可用。
控制服务的签发函数校验新鲜 Run 绑定、范围摘要和取消状态；启动发送端在
显式启用时发送凭据，未启用或签发失败时仍启动普通任务。安装期可信公钥登记、
完整取消同步和执行入口尚未接通。Linux 真机隔离测试覆盖发送端与模拟生命周期
接收端的消息、只采用 root 配置目录、开关关闭及现有生命周期回归；尚未验证
正式包上真实 root 登记的完整握手。

统一 Run 取消入口先持久化取消，再通过生命周期 socket 请求 root 创建撤销
标记。Linux 真机隔离测试覆盖真实状态写入到 root 标记的链路，以及取消未
获授权时不创建标记。通知失败仍会保留普通取消请求并记录警告；中途崩溃、
broker 不可用和直接修改状态的取消分支仍未形成完整安全保证，因此不得据此
开放特权入口。统一入口现在在 Run 状态中持久化待撤销标记，成功后清除；服务
启动时扫描状态以修复可能滞后的索引，此后定期重试。启动代次在撤销后变化时
会重新排队。Linux 真机隔离测试覆盖 broker 离线恢复、代次变化和索引落后；
该队列不是 root 实时拒绝机制。

隔离的登记执行器现在持操作锁时向本地控制服务发送一次性随机挑战，验证
固定服务公钥签名的短期状态证明，并绑定 Run、代次和 systemd InvocationID。
服务从最新状态拒绝已取消、结束或代次不匹配的 Run；服务不可用、响应伪造或
证明过期均拒绝执行。Linux 真机隔离测试覆盖真实本地路由读写的取消状态、
挑战签名和原生删除链路；原生链路的控制服务和所有者证明仍使用测试替身。
此证明依赖控制服务读取的 Run 状态：同用户 runner 对相关状态文件的可写边界
尚需完全隔离或增加不可篡改的控制面取消意图。也尚未覆盖所有取消分支、正式
包及真实用户认证，因此此检查不能单独构成生产安全保证，执行入口保持关闭。

控制服务的统一 Run 状态更新现在在发布取消或终态前，将 Run 级失效意图持久化
到控制配置目录；证明签发和范围凭据签发都检查该标记，覆盖后续启动代次。
控制目录不安全或
标记无法持久化时，显式启用该功能的取消请求会失败，不能假装撤销已成功。
真机隔离测试覆盖将共享状态改回未取消后仍被拒绝、非法请求不写意图和配置
目录权限不安全时失败。该保护依赖 runner 无法访问控制目录及服务密钥，且
控制用户的其他同 UID 进程仍在信任范围内；runner 直接写回状态而控制服务
尚未观察到的终态，以及不经过统一状态更新的路径仍需处理。

隔离登记链现在在控制目录保存不可变的 Run、启动代次、发布身份、范围摘要
和审批通道令牌摘要；不保存令牌本身。独立 runner 写入终态前可使用该 Run 的
令牌向本地控制服务请求失效，服务先持久化控制面意图。状态证明要求控制绑定
存在且与 Run 一致。Linux 真机隔离测试使用不同的 spool 所有者和 runner UID，
覆盖错误令牌、跨 session/代次拒绝、终态通知及随后篡改共享状态；测试控制
服务以 root 运行，不等同于正式包验收。

在显式启用该隔离链的 runner 中，统一状态更新现在在完成通知失败时拒绝写入
终态；普通未启用任务不受影响。若控制服务不可用期间又发生崩溃或状态篡改，
仍不能证明失效意图一定送达。多个 Run 目前共用 runner UID，能否读取彼此的
通道令牌及跨 Run 拒绝服务也须隔离；不能仅靠令牌摘要或这条本地接口宣称
完整的任务身份隔离。生产特权入口继续关闭。

完成通知现在先落盘控制面意图，再请求根生命周期服务写入撤销标记并等待
已有操作释放同一把锁；只有根侧确认后本地接口才返回成功。Linux 真机隔离
测试以不同 runner UID 写终态，验证持锁期间终态等待、释放后根标记存在，
以及 broker 离线时不返回成功但控制意图仍保留。等待超时或通知失败时，
显式启用隔离链的统一状态更新返回错误而不发布终态。未处于审批暂停的 runner
结果现在先写入暂存文件，根侧撤销确认后才发布；控制服务可核对绑定并在根侧
确认后恢复暂存，待审批结果保留原有暂停行为。真机隔离测试覆盖通知失败、
恢复和篡改发布身份的拒绝；普通任务不使用该新路径。但 runner 仍可直接写
共享文件，暂存内容本身并非防篡改证据，且待审批结果仍沿用现有共享路径。
控制服务关闭该实验开关后，已有暂存仍可在绑定验证和根撤销确认后恢复，不会
重新签发权限；根服务不可用时继续保留。另在 Linux 物理机上以普通用户运行
控制服务、独立的 `agentoc-runner` 用户写入暂存、root broker 执行撤销，
验证了跨 UID ACL、broker 离线，以及重启控制进程并关闭开关后的恢复；未验证
整机重启。完整状态隔离和故障恢复仍须处理；这些隔离夹具不等于正式包上的
真实审批及执行验收。

审批暂停解除后，控制服务读取已存在的结果前也会核对任务绑定并等待根撤销；
确认后在控制目录持久化绑定该启动代次和发布身份的完成回执。后续 broker
离线时可凭该回执读取结果；回执损坏或绑定不符时保持拒绝。真机测试覆盖
暂停、解除暂停后 broker 离线、恢复、离线读取及回执篡改，同时验证普通和
旧格式任务不受影响。回执只证明撤销屏障已确认，不证明共享结果内容真实；
同 UID runner 的跨任务访问与共享文件篡改仍未解决。

根撤销确认后，控制服务会把首次读取的非暂停结果保存到自身私有目录，后续
优先返回该副本；只有控制服务主动写入结果时才更新副本。清除 Run 结果或
删除会话会删除对应的结果副本。Linux 真机隔离测试覆盖 runner 替换或删除
共享结果、控制服务修正结果、会话删除，以及不同 UID 不能读取私有副本。
这只能保护控制服务首次采纳后的内容：runner 在采纳前仍能篡改共享结果，
同 UID 的其他 Run 仍可能访问彼此的文件，待审批结果仍走原有共享路径。
控制服务直接写入终态结果时现在先确认撤销，再在状态提交成功后更新私有
副本；提交校验失败不会更新副本。若终态与已有副本不一致，读取会返回暂时
不可用，而不是静默返回旧值。真机隔离测试覆盖 broker 离线、提交校验拒绝、
状态更正和不一致拒绝。无外部提交校验的内部终态更新现在先持久化控制目录中
的恢复记录，再写状态和副本；启动及定时扫描会在当前状态严格匹配记录的写入
前或写入后版本时恢复，不匹配时保持不可用。单独的显式取消标记防止旧完成
记录覆盖之后的取消，即使实验开关已关闭也生效。真机隔离测试覆盖控制进程
在记录落盘后被杀、重启恢复、状态冲突、并发记录竞争及取消后篡改状态。
带外部提交校验的更新仍不使用该恢复记录；记录创建时若在硬链接和清理之间
崩溃会被视为损坏并保持不可用，断电和磁盘故障仍未验收。
控制服务还会按 Run 查找所有代次的恢复记录，而不是只依赖 runner 可写的
状态代次。状态缺失或代次不符时，结果读取、写入和清除会保持不可用；
存在恢复记录时的显式取消会先为相应代次持久化撤销意图。Linux 真机隔离
测试覆盖实验开关开启和关闭时的状态删除、代次篡改以及篡改后的取消。
此检查会读取控制目录的文件名，目录规模很大时的性能尚未专项评估。

等待根撤销时，结果读取现在返回明确的暂不可用错误，而非表示结果不存在，
避免观察器进入缺失结果的合成失败分支；观察器会继续轮询并监听暂存文件，
失败的根请求按短间隔退避。控制服务自行写入已绑定任务的非暂停结果时也先
确认撤销；认证恢复和子任务结果发布不会把该错误吞成空结果，前者会重试。
Linux 真机隔离测试覆盖 broker 离线、恢复、控制服务合成结果和不同 UID，
完成效果测试覆盖子任务结果暂不可用，认证恢复的新增等待重试尚未真机注入；
Windows 相关回归通过。这仍不证明共享内容真实，
也不等同于正式包的端到端验收。

控制服务现先将 Run ID 和启动代次原子写入私有的待撤销队列，再持久化失效
意图；该队列不依赖 runner 可写的状态或索引。独立恢复任务启动时和之后定期
读取队列，只有根服务确认持久撤销并经过操作锁屏障后才移除相应队列项；失败
项轮换重试，损坏的条目保留并报警。Linux 真机隔离测试覆盖 broker 离线、
共享状态及索引被篡改、新控制进程从队列恢复根撤销和损坏条目识别。尚未模拟
断电或真实磁盘故障；通知根本未到达控制服务、控制账户等价权限被攻破、
以及队列不可写等情况仍不能保证失效，生产特权入口保持关闭。

根操作锁现按 Run 而非启动代次命名，因此一个代次的撤销屏障会等待该 Run
其他代次已经开始的操作；不同 Run 仍使用不同锁。Linux 真机隔离测试覆盖
跨代次持锁、父进程崩溃后由子进程继承锁，以及其他 Run 不受阻塞。此锁名与
旧原型不兼容：未来安装或升级必须先停止旧执行器及其全部辅助进程，不能让
新旧锁协议混跑；该升级条件尚未在正式包验证。

根登记现在从受信任的生命周期服务取得预期 runner UID，并将 systemd 主进程的
PID、内核启动时间和四个 UID 字段与单元 InvocationID 一起复核；后续读取和
续期也重新核对。短暂的 root 启动包装器有有限的降权等待，始终无法证明 UID
时不登记特权上下文。Linux 真机以非 root runner UID 测试了登记、续期、错误
UID 和错误启动时间的拒绝。旧登记记录缺少这些字段，会拒绝使用，不能静默
升级；该检查没有隔离共用同一个 runner UID 的不同任务，也不消除读取进程
身份与实际操作之间的所有竞态。

为实验性特权上下文启动的 Run 现在启用 systemd `NoNewPrivileges`，根服务
登记和每次存活复核还会检查主进程 `/proc` 中的 `NoNewPrivs`；无法确认时
拒绝登记或继续使用。普通 Run 保持原有启动方式。Ubuntu 24.04.4 真机使用
独立 systemd 单元验证：未启用该限制的单元被拒绝，启用限制的单元通过
登记、续期和撤销，root 启动包装器也能在该限制下切换至 runner 用户。
升级时旧的未受限任务无法继续使用该实验性上下文，必须
以新限制重新启动；这不隔离共享 UID，也不排除其他 IPC 或已持有权限。
根服务现在还要求主进程的 inheritable、permitted、effective 和 ambient
capability 集合均为空，因为 `NoNewPrivileges` 不会移除进程已有的能力。
真机单元在启用 `NoNewPrivileges` 的同时持有 `CAP_NET_BIND_SERVICE`，已被
拒绝登记；无这些能力的单元仍通过登记与续期。该检查针对 systemd 主进程，
不证明同 UID 的其他进程或已脱离任务边界的进程安全。

长任务续期的生命周期 socket 已提供可选的 `renew-scope` 请求。接收端只使用
root 配置的记录和公钥目录，并重新验证签名、运行代次、systemd 单元及未撤销
状态；续期、执行和撤销共用操作锁，进程崩溃不会遗留永久占用的续期锁。
Linux 真机隔离测试覆盖真实 systemd 单元经 socket 续期、旧续期锁文件残留、
伪造或旧凭据及撤销后拒绝。控制服务显式开启功能时会在启动时扫描并定期尝试
续期已有绑定，失败后重试；续期调度与撤销重试互不阻塞。Linux 真机隔离测试
覆盖 broker 离线后恢复、真实 systemd 记录续期以及取消后停止续期；控制服务
以 root 运行，未覆盖正式安装包、长时间运行或实际服务重启。超过期限仍未续期
的记录不能复活，需重新启动任务；生产权限链仍未完成。

本阶段 Linux 真机隔离测试覆盖控制服务直接写入取消和终态后，篡改共享状态
也不能恢复状态证明；运行索引测试通过。Run API 测试曾出现 409：测试会话
引用不存在的项目，后台迁移有时将其改绑，导致测试持有的作用域过期。测试
夹具改为创建并绑定真实项目后，Windows 工作树和 Linux 真机隔离快照均通过
30 项 Run API 测试；这不替代正式包和真实账户的最终验收。

Ubuntu 24.04.4 物理机上的独立 systemd 测试发现，同 UID runner 可通过用户
systemd 总线启动隔离单元之外的同 UID 进程，读取被 `InaccessiblePaths`
屏蔽的控制目录；这也可能恢复桌面用户原有的附加组。仅有挂载隔离不能作为
同用户权限边界。生命周期服务因此拒绝为同 UID 或转发桌面端点的 Run 登记
新的特权上下文，要求验证不同数值 UID；这只是限制，不证明独立 UID 的其他
IPC、桌面或文件路径已安全。现有普通 Run 与其他权限路径仍需完整安全审查，
不得把这一限制当作 Windows 等价或发行验收通过。
在同一真机的一次对照中，独立的 `agentoc-runner` UID 无法通过控制用户的
systemd 用户总线启动进程；这只验证了该总线和一次权限配置，不覆盖其他 IPC、
X11 或 Wayland，也不能替代独立身份的完整沙箱验收。

2026-11-12 在 Ubuntu 24.04.4、systemd 255 的物理机上，使用独立临时
systemd `DynamicUser` 单元测试了两任务身份：两者获得不同的 UID/GID，
各自可读自己的 0600 测试文件，不能读取对方文件及 `/proc` 环境，也不能
向对方进程发送信号。停止其中一个单元后，以同一动态用户名重建新单元，
系统重新分配了相同 UID，新进程可以读取保留在普通目录中的旧文件。
可重复的隔离夹具为 `tests/test-linux-systemd-dynamic-users.sh`；该结果
只覆盖所测机器和权限设置，不能证明所有 IPC 或文件系统安全。

因此不能直接把当前按共享 runner UID 授权的 spool、提供商凭据和工作区
ACL 改成动态 UID。实现前必须让控制面持有跨任务的秘密及状态，向每个
任务提供受身份和代次约束的最小写回通道；临时文件和 ACL 的回收必须在
UID 可被复用前完成并可证明，异常退出、broker 崩溃、系统重启、清理失败
和未受控的硬链接或复制均须考虑。现有共享 provider 服务和桌面 IPC 也需
单独设计，不能假定动态 UID 自动隔离它们。只有完整生命周期与负向测试
通过后，才能将独立任务 UID 用作特权入口的安全条件。

工作区临时组的回收现已改为先持久化释放记录，ACL 清理失败时保留组及记录，
生命周期服务会在启动后定期重试；多个任务共享组时保留各自的释放记录，
直到所有任务释放后再清理所有记录过的目录。不同执行目录的新任务不再共享
同一个组。Ubuntu 物理机使用真实 ACL 和临时组注入清理失败，验证组与 ACL
保留、后续重试清除；还用夹具检查组删除失败、旧版跨目录共享及损坏记录。
默认记录现改存 root 私有的 `/var/lib/agentoc-runner-access`；读写时持有旧
目录与新目录的锁，先持久化再移除旧记录，冲突时拒绝猜测。新记录带启动
标识，服务重启后可重试已释放记录；系统重启后可将明确属于前一次启动的
记录转入回收。旧记录没有启动标识时保守保留。Ubuntu 真机以真实 ACL、
独立进程和模拟变更的启动标识验证迁移、冲突拒绝和回收，未执行真实重启。
已经在升级前因 `/run` 清空而遗失的记录无法从此机制恢复；自定义目录的
持久性由其配置决定，任务停止时的清理命令会沿用该配置。移动或硬链接出去
的对象及 GID 复用仍未解决，不得
据此开放逐任务 UID。

### 逐任务身份的工作区挂载试验

2026-11-12 在 Ubuntu 24.04.4 x86-64 物理机（内核 7.0.0-38，ext4）上，
以私有挂载命名空间及 `open_tree`、`mount_setattr(MOUNT_ATTR_IDMAP)` 和
`move_mount` 建立一次性工作区映射。测试把原所有者 UID/GID 映射到另一个
runner UID/GID：runner 能读取和修改原有 0600 文件，创建文件在原始视图
中仍归原所有者；原文件 ACL 不变。另一 UID 无法读取该文件，runner 也不能
通过原始视图中的硬链接、映射目录内指向外部的符号链接或映射内 root 所有的
0600 文件读取未授权内容；跨挂载点创建硬链接被拒绝。测试退出后宿主机
命名空间中没有留下挂载。可重复夹具是
`tests/test-linux-idmapped-workspace.sh`，配套 C 程序仅用于隔离试验。

这为替换会遗留 ACL 的工作区访问辅助提供了一个候选方向，**尚未接入产品**。
要使用它，生命周期服务仍须验证工作区及父目录身份，隔离每个任务 UID、
凭据和结果通道，处理挂载准备失败与取消、崩溃、升级和重启，防止通过其他
IPC 或 `/proc` 获得别的任务的挂载视图；还需验证嵌套挂载、多所有者、
现有 ACL、可执行文件、不同文件系统及系统版本。不能把 UID/GID 设为系统
溢出身份，也不能在映射不支持时静默退回不安全的特权执行路径。此次不覆盖
默认 Ubuntu 24.04 内核或真实提供商，因此不是发行验收。
内核行为参见 [Linux 内核 ID 映射文档](https://docs.kernel.org/filesystems/idmappings.html)。

随后在同机使用实际 systemd 单元组合了两个 `DynamicUser` 身份和私有映射
挂载。任务在独立单元中以其中一个动态 UID 运行，`NoNewPrivs` 为 1，四组
进程 capability 为空；另一 UID 无法经 `/proc/<pid>/root` 读取该任务的挂载。
停止任务单元后进程退出，原文件的所有者和 ACL 保持不变。可重复夹具为
`tests/test-linux-systemd-idmapped-workspace.sh`，没有调用真实提供商。

该夹具还故意先停止为任务保留 UID 的独立单元：systemd 随后把相同 UID 分配
给新单元，而旧任务仍在运行；同 UID 进程能够经 `/proc/<pid>/root` 读取旧
任务的映射。因此**独立保留单元不能作为安全的 UID 租约**。生产设计必须让
UID 的保留、任务 cgroup 和所有进程的退出形成同一可验证生命周期，并处理
通过其他 IPC 逃逸及持久化文件残留，才能考虑复用该 UID。systemd 对动态
用户释放及可写目录的限制见 [systemd.exec 文档](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)。

随后同机使用 systemd D-Bus 的临时单元和 `ExecStartEx` 的 `no-setuid` 模式，
让同一个 `DynamicUser` 单元保留 UID，并由该单元内的 root 测试启动器建立
ID 映射、降权后执行任务。真实测试确认任务在该单元 cgroup 内、`NoNewPrivs`
为 1 且 capability 集合为空；另一 UID 不能经 `/proc` 读取其映射。正常
停止以及向主进程发送 SIGKILL 后，所创建的主进程和子进程均停止，systemd
运行目录消失；复用相同动态 UID 后旧运行目录内容不可见。夹具为
`tests/test-linux-systemd-single-dynamic-idmap.sh` 和其 D-Bus 启动脚本。
这只覆盖单台机器的受控测试：该 root 启动器和 D-Bus 调用尚未成为产品组件，
尚未验证进程通过 IPC 离开 cgroup、用户数据持久化、凭据和结果传递、异常
升级、实际重启或真实提供商。systemd 的 `!` 执行前缀语义见
[systemd.service 文档](https://www.freedesktop.org/software/systemd/man/252/systemd.service.html)。

为后续逐任务结果通道新增了对端身份校验组件：它要求调用方从真实 socket
取得 `SO_PEERCRED`，并以 root 可信的 Run 绑定核对 UID、GID、进程启动时间、
无新增权限、空 capability、精确任务 cgroup 和 systemd 调用代次；失效或
僵尸进程被拒绝。Ubuntu 真机通过 Unix socket 验证了任务子进程可识别、
同 UID 但属于另一个单元的进程被拒绝，以及原对端退出后即使 socket 文件
描述符仍被同单元的其他进程持有也被拒绝。
`scripts/linux-run-peer-identity.mjs` 本身不单独构成授权：
对端仍活着时可以传递已连接文件描述符，校验与实际写入之间也存在竞态；
还必须结合独立 UID、请求授权、受保护的结果保存及撤销屏障完成设计。
根上下文存储增加了供未来通道调用的组合入口：在 Run 操作锁内重新验证
签名上下文及对端，再执行内部回调，使撤销确认等待已接纳的操作结束。
真机使用真实 socket、签名 Run 上下文和 systemd 单元验证不同任务拒绝、
原对端僵尸状态拒绝、并发撤销等待及撤销后的拒绝；该入口不能解决活跃
对端转交文件描述符的问题。

根侧新增结果暂存组件：在上述身份及 Run 上下文校验和操作锁内，向 root
私有目录持久化一次结果；相同内容重试可确认，冲突内容拒绝。只有撤销
标记存在且持有同一操作锁形成屏障后，root 调用方才能读取暂存记录；读取
方还必须自行认证控制服务并检查取消意图。恢复时会清理属于该 Run 的安全
临时文件。Ubuntu 真机使用真实 systemd 单元、socket 对端身份和签名上下文
验证跨任务拒绝、重复及冲突、runner 不能读取 root 副本、撤销前拒绝读取和
撤销后读取。

新增默认不启动的 root Unix socket 服务组件，任务写入使用内核
`SO_PEERCRED` 和上述 Run 校验，读取仅允许配置的控制用户，并要求撤销屏障。
请求大小、连接数和等待时间受限；结果目录、socket 父目录及对端凭据工具
要求 root 控制。Ubuntu 真机夹具覆盖正确任务写入、同 UID 不同任务拒绝、
请求伪造字段拒绝、撤销前拒绝读取和撤销后控制用户读取。组件尚未接入产品
启动、动态 UID 任务或控制服务；实际任务命名空间还需要以最小权限暴露
socket。进程崩溃、断电、活跃对端转交文件描述符及取消意图仍须处理和完整
验证，不能当作最终写回链路。

对应客户端在发送请求前校验 root 管理的路径与凭据工具，并使用 socket 的
`SO_PEERCRED` 确认服务端 UID、GID 为 root；响应、请求和等待时间均有上限。
Ubuntu 真机夹具中，systemd 任务通过客户端写入，独立控制 UID 在撤销后读取；
另以 root 建立 socket 后降权监听并发送伪造响应，客户端拒绝该服务。客户端
已接入默认关闭的 sidecar 和控制端路径；结果采纳的取消意图由控制端另行校验。

增加独立的 systemd socket 激活入口：由 systemd 持有监听端点，broker 仅
接受预期名称的单个继承描述符，并从 root 管理的服务用户名解析控制 UID。
Ubuntu 真机通过 `systemd-socket-activate` 和独立控制 UID 验证继承 socket
读回，broker 退出时不删除该 socket；此测试不是 systemd 单元重启或安装包
验收。Debian 构建脚本安装对应单元但不启用；所需 root 目录和签名上下文
仍须在完整接入方案中配置，不能由普通任务选择。sidecar、控制端采纳、
异常重启、升级和最终包均未完成验收。

控制端 Run 绑定支持不可变的 `peer-v1` 结果通道标记；默认仍为旧通道，
当前产品启动流程尚不签发此标记。带该标记的读取必须先验证控制绑定、根
撤销回执和受保护结果的会话及轮次，不能因配置关闭或共享文件存在而回退；
显式取消后拒绝采纳非取消结果。控制端先持久化受保护结果副本，再根据副本
提交终态；后续控制端终态写入只接受与副本一致的结果和状态。
Ubuntu 真机测试了绑定不可改写、无回执
或 broker 不可用时拒绝共享结果、配置关闭后仍不回退以及不匹配的终态拒绝；
尚未完成真实 peer 结果经控制端读取、取消竞争和进程崩溃恢复的端到端验证。
读取时还会枚举控制目录中的受保护绑定；即使共享任务状态丢失或代次被
改写，也不能隐藏已绑定的 peer 通道。真机夹具覆盖了这两种拒绝情况。

清除单个 Run 结果时，控制端先为每个受保护代次持久化清除意图，再请求根侧
删除，最后清理本地副本；意图存在时读取返回空结果，即使根服务暂时不可用。
根服务仅允许控制 UID 在撤销后清除，并先持久化删除标记、再删除匹配的结果；
重复请求可完成中断的清理。真机测试覆盖非控制 UID 和撤销前拒绝、重复清除、
模拟标记已提交但旧文件残留，以及控制端请求时 broker 离线。尚未验证完整
产品链路、真实崩溃或断电。

新增默认关闭的 runner 交接路径：先通过受保护 socket 暂存结果并等待撤销，
不由 runner 发布终态；委派任务也必须等提供商退出后才能交接。Ubuntu 夹具
使用独立 runner UID、真实撤销 broker 和模拟结果 socket 验证了交接后由控制端
提交终态、取消冲突拒绝，以及模拟快照落盘而状态未写入的恢复。当前启动器
不会设置此模式；审批暂停后的继续、取消时无结果、逐任务 UID、真实结果
broker 与提供商完整链路均未验收，不能作为可发行能力启用。

补充的 Ubuntu 物理机联动夹具使用不同的非 root 控制 UID 和 runner UID、
真实 systemd 任务、签名 Run 上下文、根侧结果服务及撤销 broker，完成了
登记等待、结果暂存、撤销、控制端采纳并发布终态、清除及再次读取为空。
夹具为 `tests/test-linux-peer-handoff-systemd.mjs`；首次运行因测试 socket
账户组配置错误而未能撤销，修正后通过。该夹具直接运行测试任务入口，
不代表最终安装包、动态 UID、完整 sidecar 或真实提供商已通过验收。

随后在同一 Ubuntu 物理机使用实际 sidecar 和立即退出的模拟 Cline 子进程，
完成根侧登记、结果暂存、撤销、控制端采纳和清除。测试发现提供商在事件监听
安装前退出时，退出事件和输出可能丢失；现已在启动后立即接管事件和输出。
Codex app-server 流式场景也已回归。上述证据使用模拟提供商和独立权限夹具，
不代表真实 Codex、产品安装包或逐任务动态 UID 已完成验收。

针对取消先于结果暂存的情况，控制端在根撤销成功后保存完成回执；如果
没有可采纳的取消结果，只有收到根服务关于原 systemd 单元已停止且其
cgroup 为空的确认，才会生成取消结果。根服务对不认识的单元代次、无法
核对的单元状态和非 cgroup v2 环境拒绝确认。该路径尚未进行阶段验收，
也不能证明进程没有通过其他 IPC 离开原 cgroup；产品的逐任务身份方案
仍需完成，不因此开放特权入口。

为避免瞬时任务在根侧登记完成前执行，受保护模式下的 sidecar 在启动提供商
之前等待结果服务确认当前 socket 对端属于已登记的 Run 和 systemd 调用代次。
等待有上限，无法确认则不启动提供商。Ubuntu 真机夹具使用真实 systemd
单元和 socket 验证：登记前等待、登记后放行、同 UID 不同任务拒绝以及撤销后
拒绝。该检查只证明确认时的状态，不能排除其后立即发生的取消或对端转交
文件描述符，也尚未随产品启动链及真实提供商验收。

会话删除先核验所有受保护任务的撤销回执及禁止再次启动的意图，再逐个清除
根侧结果；服务不可用时保留会话记录，以便恢复后重试。Ubuntu 真机夹具通过
root 身份的模拟 socket 验证多任务删除、离线失败后会话仍可见和重试成功，
并回归了共享历史与普通会话删除；这尚不是实际 root broker 和真实提供商的
端到端删除验收。根结果服务端点与凭据工具可由控制服务环境指定，客户端仍
要求路径受 root 控制并验证服务身份；这两个配置不传给任务进程。

同一物理机对 systemd 管理目录作了补充试验：动态用户可在自己的
`RuntimeDirectory` 中读写，而控制用的 0600 凭据源文件不能被该 UID 直接
读取；单元通过 `LoadCredential` 获得该测试凭据。正常停止或向单元主进程
发送 SIGKILL 后运行目录被移除；同名动态用户和单元重建后，`StateDirectory`
内的旧状态仍可见。
这支持将 systemd 管理的运行目录作为后续短期通道的一部分，但不保证进程
没有把秘密复制到其他位置，也未验证 systemd 或 broker 崩溃、断电、ACL
遗留或已打开文件句柄。
不能将持久目录视为自动清理，生产接入前还须完成目录、凭据、工作区授权和
结果回传的完整生命周期及越权测试。

Linux 新 Run 的审批投影现在使用经摘要和 session 绑定校验的冻结
`executionScope.cwd` 和 `scopeRoot`，与 runner 启动目录及子目录作用域对齐；
会话目录之后变化不改变该 Run 的审批范围。旧 Run 沿用兼容路径。此摘要是
一致性检查而非签名，仍不能由 root 直接信任；特权侧必须验证服务签名、固定
公钥，并自行复核实际目录及符号链接。Linux 真机产品审批链仍待阶段验收。

适配器只对复核后的单个目标调用固定的本机文件操作，不启动 shell，也不
接受环境变量。审计分别记录授权消费、开始、完成或结果未知；崩溃后不
自动重试。结果必须同时送达用户界面和发起任务的提供商，且不得通过批准
原提供商命令造成重复执行。Codex 的审批协议没有通用文字回执，回传机制
需要单独实现和验证。

安装包必须固定组件位置、所有者、权限和版本，升级与回滚不能使旧组件
接受新授权；组件缺失、版本不符或无法核对时拒绝。旧特权命令路径、shim、
托管 MCP 和不同前端的操作必须遵循一致的策略与授权边界。

## 验收

在隔离 Linux 真机上，先验证可信父目录中的正常批准、拒绝、成功结果和
提供商回传，再覆盖不同用户伪造请求、无权限客户端、篡改授权、跨会话
复用、过期和重放、并发消费、崩溃重启、目标替换、硬链接和符号链接、
ACL、可写父目录、挂载边界、自保护目标、组件不匹配和审计故障。需验证
最终包的真实 UI 到执行器链路；模拟提供商或单元测试只能证明其覆盖范围。
