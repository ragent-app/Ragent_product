# 组织代理身份、运行时与恢复规划

状态：**实施中，尚未完成验收**，2026-11-18。本文同时记录已接通部分、剩余设计和实施顺序，不代表相关能力已全部接通或通过验收。现有共享组织、会话、授权、预算和事件后台继续作为权威；复用现有设施，不为不同 harness 复制业务内核。本文补充现有组织及 factory 规划，不替代其已冻结的契约。

## 当前依据与缺口

- `chat/system-prompt.mjs` 和 `chat/prompt-assets/system/startup-context.md` 当前注入较长的产品 API、协作、记忆和工作流说明；`chat/runtime-context-compiler.mjs` 对 Codex、Claude 恢复和其他运行时使用不同载体，不能假设每轮都传完整相同内容。`chat/harness-capability-catalog.mjs` 已能发现并在用户明确选择时注入 Ragent 托管技能全文；Codex 和 Claude 原生技能发现路径不同。Agent 的 `skills` 当前仅是标签，见 `chat/approved-agent-create.mjs`，不证明能力存在或授权。
- 组织成员现有稳定身份、关系和只读会话投影见 `chat/organization-member-aggregation.mjs` 及 Android `feature/organization`。组织提案已有 `stableKey`、角色和节点结构；名称和职责需作为明确字段补齐，不能把 stableKey 当展示名，也不能按名字猜角色、父子关系或权限。已有不同来源成员归并证据和 native 委派投影，但不能将其误述为所有 harness 均有相同控制能力。
- `chat/organization-runtime-selection.mjs` 已按部分父子策略及目录解析 tool/provider/model/effort，`chat/organization-planner.mjs` 处理节点 runtime，托管会话与派发分别见 `chat/organization-managed-session-factory.mjs` 和 `chat/organization-phase-dispatch.mjs`。静态审查发现：两个非空约束集合的空交集可能被当作无限制；这是待核实和修复的风险，尚非动态复现结论。组织目录不完整涵盖价格、配额及健康；目录查询为空时部分检查跳过。`chat/session-manager.mjs` 的部分目录异常也按 skipped 处理，不能将目录存在视为已验证可运行。
- 当前 Ragent MCP 业务读取面只有四个只读查询；`chat/runner-sidecar.mjs` 还会按授权注入其他专用 actions、browser 或 broker MCP，不应混为组织业务写入工具。当前 manager 自主委派尚未全链路接通。现有部分重试依赖错误文本，成员失败也不保证通知上级；不能声称本文的可靠中断机制已经实现。
- `lib/model-pricing.mjs` 是有限静态估价表，`chat/usage-ledger.mjs` 区分实际与估计；`lib/provider-runtime/quota.mjs` 有状态和时间戳并可能保留 stale 快照；`chat/models.mjs` 的目录带来源、版本及新鲜度。它们不构成统一、实时、完整的选型证据。

## 身份、结构与委派

每个运行仅注入短小常驻身份与不可绕过边界：当前可信 session/run/node 身份、名称、结构角色、专业职责、直属上级、授权范围及相关任务；这些值来自服务端已验证绑定，不由模型自报。权限、预算、审批和执行约束仍由服务端执行；提示和技能本身不授予权限。领导者对整体目标、分工、质量和结果负责；非根 manager 只能在实际授权子树内委派，worker/reviewer 不因文案获得管理权。

用户根会话和组织 `nodeDepth=0` 不是同一个概念。保留 `nodeDepth` 的结构语义，另算面向展示的 `displayLevel`；仅凭可信绑定将根会话与对应节点合并展示，避免重复，也不凭名称合并。节点增加 `displayName`、`responsibility`，允许任意语言并限制长度；`stableKey` 仍是稳定机器身份。上级、深度与职责来自验证后的结构；未知保持未知。

Ragent 正式组织和 Codex/Claude 等 harness 内部 subagent 的真实生命周期事件可投影为统一成员展示与通知；事件保留来源、真实绑定和可用控制能力。不能推定所有 harness 支持逐成员停止、发送消息、读取正文或恢复；缺少可信关系时不伪造根的直接子节点。

### 身份与任务字段

| 字段 | 可信含义与使用 |
| --- | --- |
| organizationId、nodeId、sessionId、runId | 服务端绑定的组织、节点、会话和本次执行身份；各自独立，不用名称替代。 |
| displayName | 节点可读名称，允许任意语言；缺失时使用明确的本地化回退，不能作为身份凭证。 |
| structuralRole、domain、responsibility | 验证后的结构角色、专业领域和职责；职责与权限分别展示，不从专业或名称推导授权。 |
| rootNodeId、rootSessionId、parentNodeId、parentDisplayName | 已验证的根与直属上级；名称只是显示，缺失关系保持未知。用户根会话与节点不能仅因都是“根”就视为同一实体。 |
| nodeDepth、displayLevel | 现有无父托管节点 nodeDepth=0；独立用户根会话 displayLevel=0，通常该首层托管节点 displayLevel=1，其余据真实关系递增。根会话实际绑定正式节点时按真实绑定去重，不套固定 +1。 |
| task、acceptance、scope、dependencies | 任务目标、验收条件、允许范围、依赖及其权威状态；缺失明确标记，不虚构验收事实。 |
| actualRuntime | 本次实际 harness、provider/profile、model、effort 与执行环境；与请求配置分开，未获运行时确认时保持未知。 |
| canDelegate、remainingDepth | 当前 run 经父级及服务端策略交集后的实际委派权与剩余深度；不可凭角色文本扩大。 |
| revision、bindingGeneration、attempt | 冻结组织版本、节点会话绑定代次与执行尝试身份，用于判定过期结果和恢复。 |

创建和每次恢复前重新验证身份、绑定、授权与版本；普通持续续接只传变化和必要约束，前提是能证明当前上下文仍包含正确身份。切换、压缩或上下文不确定时重新提供必要身份。managed run 的必要身份和权限边界不能因 `bare-user` 或其他精简模式静默跳过；若该载体无法承载则拒绝或使用可信兼容载体。

## 按任务选择运行环境

在现有领导者规划任务时提供紧凑候选表，由服务端确定性筛选，领导者在该表中为每项任务选择 harness、provider/profile、model、该模型实际支持的 effort 和执行环境；不为每个任务新增一次专门的模型路由调用。领导判断应考虑任务需求、是否确需高级模型、质量底线、完成时间、总完成成本和真实可用性；低价格不能覆盖质量或权限要求。记录选择依据与候选证据，不能伪造模型能力或质量排名。

候选首先满足任务权限、工具/环境、父子策略、预算和显式用户要求。约束交集必须区分“未约束”和“有约束但交集为空”，后者拒绝；节点身份、工作区、目标、provider 及目录来源均需匹配。用户明确指定的字段按其明确范围锁定，贯穿初次选型、默认、重试、恢复和 provider 切换；明确偏好与硬约束分别记录来源、范围和最新变更，只有用户后续明确修改才解除对应锁定。锁定项不可用时先低成本刷新可信状态、在合理期限内等待并推进不依赖它的工作；仍不可用且必须改变要求时向用户说明并询问，不能静默换模型、provider、harness、effort 或执行环境。

目录配置和缓存只是候选证据，不等于安装、认证、额度和运行均可用。按来源记录状态、时间、失效时间及 unknown；unknown 不自动算可用，也不一概永久拒绝，先使用已有低成本状态刷新或已授权检查，再通过真正的首项任务确认，无需创造收费探针。任务开始前重新校验身份、权限、目录及预算；状态变化时给出具体原因并按约束处理。跨模型 effort 不假设等价，只使用实际目录枚举；无可靠能力或质量证据时明确未知，不凭型号名称编造能力等级。

预算由用户或组织策略可选设定；无预算不代表无限授权。费用区分 provider 实际值、带来源与时效的估计、未知；订阅额度不是免费，货币不同不能直接比较，静态价格不可当实时账单。只有价格、计费方式、币种和时效可比时才作为软排序依据；无法估算总成本时保留 unknown，不把未知记为零。并发任务在派发前使用现有预算治理进行原子预留和结算，未知消耗保留相应不确定性；真实 usage 优先，明确报告覆盖不足。

### 确定性选型与记录

任务需求至少携带目标、验收质量底线、上下文规模与模态、必需工具和环境、时限、允许副作用、依赖以及用户指定范围。高级模型必要性由任务推理复杂度、歧义、专业性、错误代价、工具能力和可靠验收条件共同判断，不按 manager/reviewer 等角色自动升档。服务端先核对用户硬约束及授权，再交集筛选实际 harness、provider、模型、effort 和环境，附带来源与新鲜度；领导者在现有规划中从合格候选选择并说明理由。未知质量或可用性不得伪装为已证实，不能满足质量底线就报告阻塞。

总完成成本包括输入、缓存、输出、工具、重试和返工；按 provider 实际计费规则处理 effort/推理 token，避免在输出已包含推理时重复计费。价格、币种、套餐及来源不兼容时不排序成精确总价；估计只能作为区间与不确定性。选择记录至少保存：requested constraints 及来源、范围和版本；候选与证据版本/时间；selected resolved config；actual reported config；选择理由、成本区间及可替代范围。冻结配置不可原地改写；任何选择变化形成新版本或 attempt，关联原执行并保留历史。

## 技能、工具与上下文

短常驻层保留身份、授权边界、用户明确要求、真实性、关键恢复约束和发现方法；详细协作/API、专业流程、连接器用法放入按需技能。服务端为当前身份和工作区提供有限的名称、描述、版本与可用性索引；角色技能在已验证角色确有任务需要时加载，其他技能由任务需要或用户明确选择触发。技能内容只能指导操作，不赋予权限；访问文件、工具、网络和外部副作用仍按服务端能力及审批执行。

复用现有 Ragent 托管技能目录及显式 attach 通路，建立同一业务内核、按 Codex/Claude 原生能力实现薄适配；其他 harness 在能力不明时采用现有受控注入或不可用提示，不能假定原生 skill、MCP 或自动工具搜索已支持。业务工具统一调用现有后台，MCP 是经授权的可选入口，避免为每个 harness 实现不同业务语义。发现、挂载和调用分别核验当前 run、账户、workspace、角色及工具权限；缺少时不绕过。

技能来源须限制在可信根路径，记录内容版本或哈希；身份、授权、工作区、目录或内容改变时使相关缓存失效。应用缓存只减少文件读取，不证明模型上下文仍持有内容。新线程、压缩、harness/provider 切换或无法证明续接包含技能时，按当前任务重新提供必要内容；避免盲目重复注入，也不因历史标记漏掉必要规则。短描述索引、按需正文和 MCP schema 均有上下文成本，具体由实际运行时注入、缓存与计费决定，不能承诺固定节省比例。

### 技能与角色最小模块

| 模块 | 直接提供的最小说明 | 按需读取 |
| --- | --- | --- |
| Root | 整体目标、用户约束、可委派范围、真实状态与最终责任。 | 组织规划、复杂协调及相关专业流程。 |
| Manager | 直属上级、子树边界、剩余深度、分工和向上报告义务。 | 子树委派、冲突处理与恢复流程。 |
| Worker | 任务、范围、依赖、验收和向上报告义务。 | 实际任务对应专业技能及连接器。 |
| Reviewer | 独立审查范围、只读权限、验收标准及证据要求；不主动修复。 | 相应审查流程和专业材料。 |

身份、授权、任务和必要协作说明直接提供；可选连接器、格式、API 细节和领域流程按需读取。Codex/Claude 优先使用其实际可用入口；原生入口不可用时，在现有授权范围内增加轻量技能读取入口并复用既有 resolver，不以先建新检索系统为前提。目录发现、读取授权和实际工具执行是三次不同判断。

### 拟议业务工具与角色边界

| 能力 | 目标调用者及边界 |
| --- | --- |
| 候选查询 | 具备该任务授权的 root/manager 查询经服务端筛选的候选，不返回凭据。 |
| 组织状态与变化 | 授权成员读取自己任务和允许子树的状态、事件及游标；root 读取其授权组织。 |
| 方案提交与调整 | 有实际授权的 root 或 manager 提交其范围内提案；冻结版本调整须走现有修订、校验与并发控制。 |
| 受限子树委派 | 仅具实际 canDelegate 和剩余深度的调用者，在授权子树、预算及并发上限内使用。 |
| Team 消息 | 按实际成员绑定与授权发送或读取；不能凭展示关系取得通信权。 |
| 结果与阻塞 | 执行者按自身 attempt 提交证据或阻塞；上级读取并处理，服务端事实独立记录。 |
| Review | 经授权的 reviewer 提交独立审查结果；决定与证据保留来源，不等于执行权限。 |
| 恢复决策 | 在实际授权范围内请求核对、续接、重试或重新分派；服务端执行幂等、预算和安全校验。 |

以上是业务能力设计，不代表已有对应 MCP 写工具。owner 专用接口不得通过 MCP 借用 owner 身份包装给成员；合法既有授权内可自动推进，无须对每个动作追加审批，但必要审批和用户边界不可绕过。区分请求接收、校验、创建、启动和完成，逐项以服务端响应确认。同一次组织操作只走一个执行入口，防止工具提交与文字解析重复创建；迁移完成后删除重复路径，不长期双写。

## 中断、通知与受控恢复

后台独立观察 run、进程和传输，不依赖已崩溃成员自行报告。持久记录可信结构化原因、来源、时间、绑定、run/attempt 及脱敏证据引用；成员的业务解释单独保存，不能覆盖系统事实。区分普通工具错误、明确任务失败、限流、认证或额度、网络中断且结果未知、审批暂停、取消、进程崩溃；未知就是未知，不将任意文本推断为权威分类。

事件经稳定 ID 去重后通知直属上级，上级忙时持久排队，服务重启后恢复；未处理或超时按授权升级到根。送达、已读和处理是不同状态，不能因发送成功宣称已处理。迟到结果应按原 run 和绑定核对后更新事实，不复活已取消或过期执行，也不覆盖新 run 的结果。通知与恢复应幂等并保留审计链。

恢复顺序：先核实原 run 和外部副作用结果，再在支持且安全时续接；只有确定可重复才按同一约束安全重试，必要时在授权范围内重新分派。所有层共享单一总重试/退避/期限控制，避免嵌套无限重试；网络超时且副作用结果未知时先对账，禁止盲目重跑。使用执行代次、租约或同等既有机制防止旧、新 run 并发写入；额度或认证错误不能自动升级更昂贵模型。跨 harness/provider 不假设原会话、工具状态或副作用可移植，只传可验证的受控交接；改变用户锁定项须遵守前述规则。

### 中断处理与通知契约

| 事件 | 响应 |
| --- | --- |
| 低风险工具错误 | 成员可在权限和总重试限额内自修；每条错误不必唤醒上级，持续阻塞或耗尽限额才升级。 |
| 明确任务失败或进程崩溃 | 后台记录事实并通知直属上级；核对 run 与副作用后决定恢复或升级。 |
| 限流 | 按可信限流信息和期限退避；不得因额度错误自动升级模型。 |
| 认证/额度 | 标明具体可验证边界，刷新低成本状态；按锁定及授权等待、处理或请求用户。 |
| 网络中断、结果未知 | 保留未知状态和成本预留，核对原 run 和外部结果；不得盲目重跑。 |
| 审批暂停 | 使用独立审批期限和等待状态，不计作普通超时失败；审批结果仍以权威系统为准。 |
| 用户或上级取消 | 记录取消并阻止自动重试；迟到结果按原 attempt 处理。 |

分类使用结构化事件、可信进程和传输状态；不能仅靠错误关键词。通知至少包含组织、成员、直属上级、任务及 attempt/run、类别、发生时间、事实可信度、脱敏证据引用、影响与当前待办；成员解释单独标记。记录通知的送达、已读、上级确认和故障解决状态，确认不是解决。父级失败时沿真实上级链升级；恢复后记录处理结果。UI 在实时动作行只显示必要、简短且真实的异常与状态，后台限制重复通知与重试风暴。

## 六阶段实施与验收

| 阶段 | 交付物 | 依赖与验收标准 |
| --- | --- | --- |
| 1 身份约束 | 可信身份字段、绑定/层级、约束交集语义。 | 依赖现有组织和授权数据；以既有可信检查及真实投影确认绑定、未知和空交集拒绝。 |
| 2 候选选型 | 候选证据、硬约束、选择记录及派发前复核。 | 依赖阶段 1；真实任务验证显式指定、不可用和费用未知不静默替换。 |
| 3 工具技能 | 角色最小上下文、按需技能及 Codex/Claude 薄适配。 | 依赖阶段 1 授权；确认技能发现、读权限与业务调用分别受控，其他 harness 如实降级。 |
| 4 中断反馈 | 后台观察、持久通知、升级与处理状态。 | 依赖阶段 1 身份和事件；真实可观察故障证据确认去重、恢复队列及原因可信度。 |
| 5 受控恢复 | 对账、续接、总重试、代次隔离及成本预留。 | 依赖阶段 2 和 4；以已有可信检查和授权真实场景确认未知副作用不盲重跑。 |
| 6 验收与成本 | 代表性实际任务的质量、时延、用量和限制记录。 | 依赖相关阶段完成；比较整个任务输入、缓存、输出、工具、重试和返工，不承诺固定 token 节省。 |

所有阶段按 Evidence First 复用可信现有检查和用户已授权真实任务；不为证明进度使用自造案例或新增付费探针；用户授权的真实模型任务可用于验收，新增测试须先获许可。

界面保持简约，只呈现可信的身份、真实状态和需要处理的异常；不恢复已删除的两条成员 coverage 提示。阶段完成以实际代码和证据为准，不以本文为实现证明。
